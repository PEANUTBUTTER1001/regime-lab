# regime-lab

> **과거 데이터 분석 도구이며 투자 권유가 아닙니다.** (Historical analysis — not investment advice.)
> 목표가·투자 비중·종목 추천·매매 신호를 제공하지 않습니다.

regime-lab은 **코스피·코스닥 일봉 데이터로 기술적 매매 패턴을 백테스트하고, 그 성과가 시장 환경에 따라 어떻게 달라지는지 확인하는 분석 서비스**입니다.

"이 패턴이 과거에 수익을 냈는가?"에서 한 걸음 더 나아가 다음을 함께 확인합니다.

- 상승장·횡보장·하락장 중 **어떤 국면에서** 성과가 났는가?
- **대형주·중형주·소형주**, 코스피·코스닥 중 어디에서 성과가 났는가?
- 그 성과가 **우연이 아니라고 볼 근거**가 있는가? (3중 검증)

## 무엇을 할 수 있나

| 기능 | 설명 |
|---|---|
| 전략 만들기 | 매수 패턴 14종을 AND/OR로 조합하고, 손절·익절·최대 보유 기간(선택: 트레일링·본전·이동평균 이탈), 시장·기간·거래대금 하한·시총 그룹을 정합니다 |
| 백테스트 | 신호 다음 날 시가에 매수하고, 상한가·하한가·거래정지·상장폐지, 왕복 비용 0.30%를 반영합니다 |
| 실행 결과 | 판정(분석 대상 여부)과 3중 검증을 먼저 보여 주고, 핵심 지표·국면별 성과·자산곡선·수익률 분포를 표시합니다. 같은 화면의 탭에서 종목별 거래와 AI 보고서를 봅니다 |
| 국면별 분석 | 시장 국면 × 시장 × 시가총액 그룹별 성과를 표시하고, 거래 300건 미만 칸은 "표본 부족"으로 구분합니다 |
| 3중 검증 | ① 기간 분할(2024-02-29 전후) ② 다중검정 보정(BH-FDR) ③ 무작위 진입 1,000회 비교. 셋 다 통과해야 "분석 대상"으로 표시합니다 |
| 목표로 전략 찾기 | 목표 승률을 정하면 범위 안의 조합을 모두 같은 규칙으로 평가해 과거에 목표를 충족한 후보 전략을 찾습니다(역방향 백테스트). 탐색 구간에서 고르고 평가 구간에서 다시 확인합니다 |
| 저장한 전략 | 찾았거나 직접 만든 전략을 기본값까지 고정해 저장하고, 전략 만들기로 불러와 다시 실행합니다 |
| AI 보고서 | 결과를 한국어로 해설합니다. 결과에 없는 숫자나 권유 표현이 나오면 자동으로 막습니다 |
| 공시·뉴스 | 기준 시각에 이미 알 수 있었던 공시·뉴스만 검색하고 목록으로 봅니다(수집 자료가 있을 때) |

**사용 데이터**: 코스피·코스닥 전 종목 일봉, 2020-09-01 ~ 2026-09-18 (상장폐지 종목 포함)

**매수 패턴 14종**

| 묶음 | 패턴 | 조건 (쉬운 설명) |
|---|---|---|
| 핵심 | 5/20 골든크로스 | 5일선이 20일선을 아래에서 위로 뚫은 날 |
| 핵심 | 20일 고가 돌파 | 종가가 직전 20거래일 최고가를 넘은 날 |
| 핵심 | 거래량 동반 돌파 | 20일 고가 돌파 + 거래량이 직전 20일 평균의 2배 이상 |
| 핵심 | RSI 회복 | RSI(14)가 30 아래에서 30 이상으로 회복한 날 |
| 핵심 | 볼린저 하단 회복 | 종가가 볼린저 하단(20일, 2σ) 아래에서 다시 안으로 들어온 날 |
| 후순위 | 연속 하락 뒤 반등 | 며칠 연속 내린 뒤 오른 채로 마감한 날 |
| 후순위 | 볼린저 수축 돌파 | 가격 움직임이 아주 좁아졌다가 위쪽으로 크게 벗어난 날 |
| 후순위 | 20일선 눌림목 | 오르는 20일선까지 잠깐 내려왔다가 다시 그 위로 마감한 날 |
| 후순위 | 그랜빌 매수 1법칙 | 200일선이 오름세로 돌아서는 날 가격이 그 선을 위로 뚫은 경우 |
| 후순위 | 상승 장악형 | 며칠 내린 뒤, 오른 날의 몸통이 전날 내린 몸통을 완전히 덮은 경우 |
| 추가 | MACD 골든크로스 | MACD가 시그널선을 아래에서 위로 넘은 날 |
| 추가 | 52주 신고가 돌파 | 종가가 직전 250거래일 최고가를 처음 넘은 날 |
| 추가 | 이격도 과매도 반등 | 가격이 20일 평균보다 크게 낮아졌다가 다시 가까워지기 시작한 날 |
| 추가 | 스토캐스틱 과매도 반등 | 과매도 구간에서 %K가 %D를 위로 넘은 날 |

정확한 계산식은 전략 만들기 화면의 **계산식 보기**에서 볼 수 있습니다. 일부 패턴 수치(기간·배수·문턱)는 허용 범위 안에서 바꿀 수 있습니다.

## 빠른 시작

### 준비물

- Windows / macOS / Linux, **Python 3.12**, [uv](https://docs.astral.sh/uv/)
- 메모리 8GB 이상 (실행 중 최대 약 2.4GB 사용)
- 원본 데이터: 저장소 루트에 `data`(시세 데이터)와 `multi_tables_db/`(SQL 덤프). **저장소에는 포함되지 않습니다.**

### 처음 한 번

아래 명령은 모두 **저장소 루트**(`regime-lab/`)에서 실행합니다.

1. 패키지를 설치합니다.

```bash
uv sync --project engine
```
```bash
uv sync --project api
```

2. SQL 덤프에서 워밍업용 가격과 참조값을 추출합니다(약 20초, 결과는 `cache/`에 저장).

```bash
uv run --project engine python engine/scripts/extract_sqldump.py
```

3. 과거 지수(2019-08~2020-08)를 받아 둡니다(인터넷 필요, 몇 초). 받아 두면 시장 국면이 2020-09-01부터 계산됩니다. 건너뛰면 지수 이력 부족으로 2021-07-21부터 계산됩니다.

```bash
uv run --project engine --with finance-datareader python engine/scripts/fetch_index_history.py
```

4. 분석용 데이터를 미리 계산해 둡니다(약 40초). 이후 서버는 1초 안에 데이터를 불러옵니다.

```bash
uv run --project engine regime-lab prepare
```

### 데이터 서버에서 받기 (데이터 서버 PC 전용)

> **2026-10-14 결정 F1d:** 원본은 데이터 서버 PC 에서만 관리·보관합니다. 팀원 PC 는 원본을 받지 않고, 팀 서비스는 서버 PC 에서 띄운 웹을 브라우저로 씁니다. 아래 절차는 서버 PC 안에서 쓰는 방법입니다. 새 시세(2026-09-19~)의 출처는 공공데이터포털 "금융위원회_주식시세정보"(공공누리 제4유형: 출처 표시·상업적 이용 금지·변경 금지)입니다.

팀 데이터 서버의 조회 API 에서 시세 원본을 받아 위 `data` 와 같은 형식으로 저장합니다(F1). 서버 주소는 담당자(Seonghwanaa)에게 직접 받고, 저장소·채팅에 적지 않습니다. 이 PC 의 IP 가 서버 허용 목록에 있어야 합니다. 자세한 내용은 [`docs/F1_데이터_서버_API.md`](docs/F1_데이터_서버_API.md).

1. 서버 주소를 이 터미널에만 넣습니다(서버가 인증을 켰다면 `REGIME_DATA_API_TOKEN` 도).

```powershell
$env:REGIME_DATA_API_URL = "http://<서버주소>:<포트>"
```

2. 새 폴더로 받습니다. 원본이 없는 PC 는 `--no-compare` 와 sample30 종목(`--sample-tickers`, 담당자에게 받음)을 줍니다. 원본이 있는 PC 는 두 옵션 없이 실행하면 기존 원본과 겹치는 기간을 대조해 같을 때만 저장합니다. 봉 예측까지 쓰려면 `--minutes` 를 더합니다(수 GB, 오래 걸림).

```bash
uv run --project engine python engine/scripts/sync_data_server.py --out ../regime-data-sync --no-compare --sample-tickers <30종목, 쉼표 구분>
```

3. `engine/config/paths.local.yaml` 의 `store` 를 받은 폴더(`../regime-data-sync/store`)로 바꾸고, 위 3번(과거 지수)·4번(`prepare`)을 실행합니다. 2번(SQL 덤프 추출)은 덤프가 없으면 할 수 없습니다. 이 경우 지표 워밍업(2019-08~2020-08)과 상장 거래일 보정 없이 계산되어 **기간 초반 약 250거래일의 지표·대상 종목이 덤프가 있는 PC 와 달라지고**, 워밍업·참조값 테스트는 skip 됩니다. 같은 결과가 필요하면 덤프 추출물(`cache/warmup`·`cache/reference`)을 가진 팀원에게 받습니다.

### 실행

```bash
uv run --project api regime-api
```

브라우저에서 **http://127.0.0.1:8000** 을 엽니다. 끌 때는 서버를 실행한 창에서 `Ctrl+C`를 누릅니다.

기본은 **데모 모드**입니다. 이 PC(127.0.0.1)에서만 열리고, 실제 인증 없이 게스트 모드나 데모 로그인으로 들어갑니다. 실제 계정으로 로그인하려면 아래 "로그인 모드"를 보세요.

## 로그인 모드

| 모드 | 켜는 법 | 동작 |
|---|---|---|
| 데모 (기본) | 아무 설정 없이 실행 | 이 PC에서만 열립니다. **테스트용 게스트 로그인**으로 들어갑니다(실제 인증 아님). 실행 기록·저장한 전략은 이 서버를 쓰는 모두가 함께 봅니다 |
| Supabase | 아래 환경변수를 설정하고 실행 | 카카오·Google 로그인과 테스트용 게스트 진입을 제공합니다. `auth.guest_enabled`로 게스트 허용을 조절합니다. 게스트별 기록도 격리되며 로그아웃·세션 만료 후 다시 접근할 수 없습니다. 실행·탐색·저장한 전략은 **본인 것만** 보이고, 소유자가 기록되지 않은 과거 실행은 보이지 않습니다 |

다른 PC에서 카카오·Google·게스트 로그인을 실행하려면 **[팀원 로컬 실행 안내](docs/X3_팀원_로컬_실행.md)**를 순서대로 따라 하세요. 저장소 받기, PR 병합 전/후 브랜치 선택, Windows·macOS/Linux 환경변수, 접속 주소, 확인 방법을 한곳에 정리했습니다.

팀에서 함께 쓰는 값은 Supabase 프로젝트 URL과 공개 publishable key 두 개입니다. 각 PC는 자기 로컬 서버를 실행하며 `127.0.0.1`은 그 PC 자신을 뜻합니다. 작성자의 PC 경로·실행 파일·로그인 세션을 복사할 필요가 없습니다. 이 Python 서버는 `REGIME_*` 환경변수를 읽으며 `NEXT_PUBLIC_*`만 설정해서는 적용되지 않습니다.

Supabase 로그인 연결이 시세·뉴스 자료나 실행 결과를 다른 PC로 복사하지는 않습니다. 로그인만 확인할 때는 뉴스 수집기·DB 연결이 필요하지 않습니다. 백테스트용 시세 준비는 위의 "처음 한 번", 뉴스 DB 자동 조회는 해당 기능의 PR #81 실행 안내를 따릅니다.

## 사용 방법

왼쪽 사이드바는 작업 순서대로 묶여 있습니다.

| 묶음 | 메뉴 |
|---|---|
| 전략 시험하기 | 전략 만들기 · 목표로 전략 찾기 · 저장한 전략 · 백테스트 기록 |
| 결과 보기 | 실행 결과 (화면 안의 탭: 요약 · 종목별 거래 · AI 보고서) |
| 공시·뉴스 | 공시·뉴스 검색 · 공시·뉴스 목록 |
| 시장 참고 | 시장 브리핑 (준비 중) |

어려운 용어 옆의 **?** 를 누르거나 마우스를 올리면 쉬운 설명이 나옵니다(키보드 Tab으로도 열립니다).

### 1. 시작하기

데모 모드에서는 **테스트용 게스트 로그인**으로 들어갑니다. Supabase 모드에서는 **카카오로 계속하기** 또는 **Google로 계속하기**를 누릅니다. 첫 이용 시 Supabase 계정이 생성되며, 허용된 경우 테스트용 게스트로도 진입할 수 있습니다.

### 2. 전략 만들기

세 단계를 차례로 정합니다. 오른쪽 **내 전략 요약**에 입력한 내용이 문장으로 바로 정리되고, **예상 대상 종목 수**도 함께 표시됩니다.

| 단계 | 입력 |
|---|---|
| 1. 언제 살까 (매수 조건) | 패턴을 1개 이상 고르고, 여러 개면 AND(모두 충족) 또는 OR(하나라도 충족)를 고릅니다. **계산식 보기**를 켜면 패턴마다 정확한 계산식이 보입니다 |
| 2. 언제 팔까 (매도·청산 규칙) | 손절(-50 ~ -1%), 익절(+1 ~ +200%), 최대 보유(1 ~ 250거래일). 손절·익절은 "사용"을 끄면 적용하지 않습니다. **추가 매도 조건(선택)** 에서 트레일링 스톱·본전 스톱·이동평균 이탈 청산을 켤 수 있습니다 |
| 3. 무엇을, 언제 (대상 종목·기간) | 시장, 신호 기간, 20일 평균 거래대금 하한(5억 원 이상), 시총 그룹 |

화면 아래 실행 막대에 전략 이름을 적고 **백테스트 실행**을 누르세요. 입력이 허용 범위를 벗어나면 해당 칸 아래에 이유가 표시되고 실행되지 않습니다. 같은 조건을 다시 쓰려면 요약 패널 아래 **전략 저장**으로 저장합니다.

### 3. 진행 상황

필터 → 로드 → 지표 → 신호 → 국면 → 집계 → 저장 단계가 순서대로 표시됩니다. 전 종목 기준 약 13초 걸리며, 끝나면 결과 화면으로 자동 이동합니다. **실행 취소**를 누르면 결과를 남기지 않고 중단합니다.

> 계산은 한 번에 하나씩 처리합니다. 다른 사람의 실행·탐색이 진행 중이면 접수 순서대로 대기하며, 진행 화면에 대기 순번과 취소 버튼이 표시됩니다. 기본 대기 상한은 5건입니다. 본인의 대기·실행 중 작업은 1건까지이며, 다시 실행하면 해당 작업을 확인합니다(데모 모드는 접속 IP 기준).

### 4. 실행 결과 읽기

| 영역 | 보는 법 |
|---|---|
| 판정 | 맨 위에 **분석 대상입니다 / 아닙니다**가 표시됩니다. 분석 대상은 과거 데이터에서 우연이 아닐 가능성을 확인했다는 뜻이며 앞으로의 수익을 뜻하지 않습니다 |
| 검증 3종 | "앞뒤 기간 모두 시장보다 나았나요?(기간 분할)", "우연히 좋아 보인 것은 아닌가요?(거짓 발견 통제)", "아무 날에나 산 것보다 나았나요?(무작위 벤치마크)" 세 질문의 결과와 상세 수치 |
| 핵심 지표 | 거래 수, 승률, 평균 순수익률(비용 차감 후), 평균 초과수익(같은 기간 시장 지수 대비) |
| 자세한 지표 | 무작위 백분위, 중앙값 순수익률, 손익비, 샤프, 최대낙폭, 제외/진입 스킵. "무작위 백분위 99.7"은 같은 종목·보유기간으로 무작위 진입한 결과 중 99.7%보다 높다는 뜻입니다(수익률이 아님) |
| 자산곡선 | 동시 보유 종목을 같은 비중으로 담았을 때의 일별 자산. 아래 막대를 끌어 기간을 확대할 수 있습니다 |
| 국면 × 시가총액 | 국면별·시총 그룹별 평균 초과수익. **빗금 칸은 거래 300건 미만**이라 결론에 쓰지 않습니다 |
| 종목 표 | 수익률이 아니라 **거래 수 순**으로 정렬합니다. 행을 누르면 종목별 거래로 이동합니다 |

손익 색은 한국 증권 앱과 같습니다. **수익·상승은 빨강 ▲, 손실·하락은 파랑 ▼** 이며 +/− 부호도 함께 표시합니다. 오류나 미통과 표시는 주황입니다. 각 차트 위에는 "이 차트로 보는 것" 한 줄이 있고, 지표의 계산식은 결과 화면 맨 아래 **지표 정의**에서 볼 수 있습니다.

### 5. 종목별 거래와 AI 보고서

결과 화면 위쪽 탭으로 이동합니다.

- **종목별 거래**: 가격과 20·200일선, 종목 국면(상승 빨강·하락 파랑 배경), 과거 진입(빨강 ▲)·청산(파랑 ■) 시점, 거래 내역을 보여 줍니다.
- **AI 보고서**: 같은 실행 결과를 한국어로 해설합니다. 상단 표시로 종류를 구분합니다.
  - **숫자 검증 통과**: AI가 쓴 문장이 검증을 통과한 경우
  - **템플릿 보고서**: AI를 쓸 수 없거나 검증에 실패해 정해진 문장으로 대신한 경우

### 6. 목표로 전략 찾기와 저장한 전략

- 맨 위 줄에 **탐색 이름 · 목표 승률 · 최소 거래 수**를 정하고, 아래 **탐색 범위**(패턴·결합·손절·익절·보유일)와 **대상·기간**을 고릅니다. 고른 값의 모든 조합이 후보 전략이 됩니다.
- 오른쪽 아래에 떠 있는 **탐색 실행** 버튼 위에 후보 수와 예상 시간이 표시됩니다. 후보가 상한을 넘으면 범위를 줄이세요.
- 결과는 후보마다 탐색 구간·평가 구간 성과와 검증을 함께 보여 줍니다. 순서는 상태 순이며 순위나 추천이 아닙니다. 마음에 드는 후보는 **전략으로 저장**할 수 있습니다.
- 지난 탐색은 제목 오른쪽 **최근 탐색 기록** 버튼으로 다시 엽니다.
- **저장한 전략**에서 이름 바꾸기·삭제, **전략 만들기로 불러오기**를 합니다.

### 7. 공시·뉴스

OpenDART 공시 등 수집한 외부 자료가 있을 때 쓸 수 있습니다(수집 방법은 [`ingest/README.md`](ingest/README.md), 위치는 `engine/config/paths.local.yaml`의 `ext_store`). 자료가 없으면 "데이터 없음"으로 표시됩니다.

- **공시·뉴스 검색**: 기준 시각에 이미 알 수 있었던 자료만 제목·회사명으로 찾습니다. 비슷한 제목은 하나로 묶습니다.
- **공시·뉴스 목록**: 출처 유형·기간·종목·상태로 거르고, 자료 상세에서 버전 이력과 정정 관계 후보를 봅니다. 권한상 원문 대신 출처 링크로 안내합니다.

### 8. 설정

사이드바 맨 아래 **⚙ 설정**에서 화면 언어를 **한국어(기본) / English**로 바꿀 수 있습니다. 선택은 이 브라우저에 저장됩니다. AI 보고서 본문은 언어 설정과 관계없이 한국어입니다. 같은 화면에서 AI 보고서용 모델명·API 키도 입력합니다(아래 "ChatGPT 보고서 켜기").

> **시장 브리핑**은 야간 시세·뉴스 데이터가 아직 없어 "준비 중"으로 표시되며, 열면 "데이터 없음"만 보여 줍니다.

## ChatGPT 보고서 켜기 (선택)

키가 없으면 AI 보고서는 템플릿으로 동작합니다.

**방법 1 — 설정 화면 (권장)**: 서버를 켠 뒤 사이드바 **⚙ 설정 → AI 보고서**에 OpenAI 모델명과 API 키를 넣고 **적용**을 누릅니다. 다음 AI 보고서부터 바로 쓰입니다.

- 키는 서버 메모리에만 보관되고 **서버를 끄면 지워집니다**. 파일·브라우저에 저장되지 않으므로 서버를 다시 켜면 다시 입력하세요.
- 화면에는 키의 마지막 4자리만 표시됩니다. **지우기**를 누르면 서버 시작 시의 환경변수 값으로 돌아갑니다.
- 이 PC에서 연 화면에서만 바꿀 수 있습니다. Supabase 모드에서는 `REGIME_AUTH_ADMIN_IDS`에 등록한 관리자만 바꿀 수 있습니다. 입력 방식은 잠정이며 추후 다시 정합니다(결정 E10, 과제 T-9).

**방법 2 — 환경변수**: 서버를 켜기 전에 설정합니다(PowerShell 예시). 설정 화면 입력 값이 있으면 그 값이 우선합니다.

```powershell
$env:REGIME_LLM_MODEL = "<사용할 OpenAI 모델명>"
```
```powershell
$env:OPENAI_API_KEY = "<발급받은 키>"
```
```powershell
uv run --project api regime-api
```

API 키는 코드나 파일에 적지 말고 환경변수로만 넣으세요. AI에는 집계된 결과 수치만 보내고, 원본 시세나 개인정보는 보내지 않습니다.

## 명령줄로 사용하기 (선택)

화면 없이 전략 파일(YAML)로 실행할 수도 있습니다. 결과는 `runs/<실행 ID>/`에 저장됩니다.

전략 1개 실행:
```bash
uv run --project engine regime-lab run engine/strategies/core_breakout_vol.yaml
```

여러 전략 비교 실행(한 번의 실행으로 묶어 다중검정 보정을 적용):
```bash
uv run --project engine regime-lab run engine/strategies/core_breakout_20d.yaml engine/strategies/core_breakout_vol.yaml
```

핵심 5종 한꺼번에 실행(약 75초):
```bash
uv run --project engine regime-lab batch
```

전략 파일 작성법은 `engine/strategies/example_breakout_and_rsi.yaml`을 참고하세요.

그 밖의 명령:

| 명령 | 하는 일 |
|---|---|
| `uv run --project engine regime-lab rag-index` | 공시·뉴스 검색 색인을 만듭니다 (`ext_store` 필요) |
| `uv run --project engine regime-lab rag-search "<검색어>" --as-of <시간대 포함 시각>` | 기준 시각에 보이던 자료만 검색합니다 |
| `uv run --project engine regime-lab forecast-run --timeframe 1h` | 과거 시점별 봉 예측을 만들어 `runs/forecasts/`에 저장합니다 (1분봉 사본 필요, 화면은 준비 중) |

## 문제 해결

| 증상 | 해결 |
|---|---|
| `error while attempting to bind on address ('127.0.0.1', 8000)` | 이미 서버가 켜져 있습니다. 기존 창에서 `Ctrl+C`로 끄거나 다른 포트를 씁니다: `$env:REGIME_PORT = "8001"; uv run --project api regime-api` |
| 화면에 "데이터 불러오는 중"이 계속 표시됨 | 분석용 데이터를 계산하는 중입니다. `regime-lab prepare`를 먼저 실행해 두면 1초 안에 뜹니다 |
| AI 보고서가 "템플릿 보고서"로 나옴 | 모델명·키가 설정되지 않았거나(서버를 다시 켜면 설정 화면 입력 값은 지워집니다) AI 문장이 검증에서 걸렸습니다. 화면의 대체 사유를 확인하세요 |
| 종목별 거래에 "오래된 결과" 표시 | 설정이나 데이터가 바뀌기 전의 실행입니다. 다시 실행하세요 |
| 로그인 화면에 게스트 버튼이 없음 | Supabase 모드로 켜진 서버입니다. 계정으로 로그인하거나, 환경변수 없이 데모 모드로 켜세요 |
| 서버를 다시 켰더니 로그아웃됨 | Supabase 모드의 로그인 세션은 서버 메모리에만 있습니다. 다시 로그인하세요 |
| 30종목으로 빠르게 시험하고 싶음 | `$env:REGIME_SAMPLE = "1"`을 설정한 뒤 서버를 켭니다 |

## 프로젝트 구성

```text
regime-lab/
├─ engine/     분석 엔진 (Python) — 데이터·지표·국면·패턴·백테스트·검증·근거 검색·봉 예측, CLI
├─ api/        실행·결과 API (FastAPI) — 웹 화면 서빙, AI 보고서, 로그인
├─ ingest/     공시·뉴스 수집기 (OpenDART 등)
├─ web/        웹 화면 (HTML/JavaScript) — 한국어·영어
├─ docs/       기획·결정·계획 문서
├─ store/      원본 시세 데이터 (저장소 미포함)
├─ cache/      추출·계산 데이터 (자동 생성, 저장소 미포함)
└─ runs/       실행 결과 (자동 생성, 저장소 미포함)
```

테스트:
```bash
uv run --project engine python -m pytest engine
```
```bash
uv run --project api python -m pytest api
```
```bash
uv run --project ingest python -m pytest ingest
```
