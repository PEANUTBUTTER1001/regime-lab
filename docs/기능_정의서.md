## 1. 기능 분류와 우선순위

| 그룹 | 기능 | 우선순위 |
|---|---|---|
| DATA | 데이터 수집·품질·유니버스·국면 | Must |
| BT | 전략 구성·백테스트·검증 | Must |
| UI | 전략 빌더·진행·결과·상태 화면 | Must |
| API | 비동기 실행과 결과 조회 | Must |
| BRIEF | 야간 시장·테마·모닝 브리핑 | Must |
| AI | AI 보고서·자연어 전략 변환 | 보고서 Must / 변환 Should |
| PATTERN | 유사 패턴 과거 사례 비교 | Should |
| ML | 거래 필터 실험 | Should |

## 2. 데이터·분석 기능

### F-D01. 일봉 데이터 및 유니버스 구성

| 항목 | 정의 |
|---|---|
| 목적 | 백테스트에 사용할 신뢰 가능한 종목·지수·시가총액 데이터를 준비한다. |
| 입력 | 수정주가 일봉, 종목 마스터, KOSPI/KOSDAQ 지수, 일별 시가총액 |
| 처리 | 종목 유형·유동성·상장 기간 조건으로 유니버스를 구성하고 제외 사유를 기록한다. |
| 출력 | 분석 유니버스, 제외 목록, 데이터 품질 결과 |
| 예외 | 누락·중복·수정주가 불확실·기간 부족 데이터는 품질 실패 또는 제외로 처리한다. |
| 완료 기준 | 기간, 종목 수, 결측, 제외 사유를 조회할 수 있다. |

### F-D02. 시장·종목 국면 산출

| 항목 | 정의 |
|---|---|
| 목적 | 같은 전략을 시장·종목 환경별로 비교한다. |
| 입력 | 기준일까지의 지수 및 종목 일봉 |
| 처리 | 200일선 위치와 20일 기울기로 bull, sideways, bear를 판정한다. |
| 출력 | 날짜·종목별 시장 국면과 종목 국면 |
| 제약 | t일 국면은 t일 이후 데이터를 사용하지 않는다. |
| 완료 기준 | 입력 데이터의 끝을 잘라도 이전 구간의 국면이 바뀌지 않는다. |

### F-D03. 야간 시장·뉴스·테마 입력 검증

| 항목 | 정의 |
|---|---|
| 목적 | 모닝 브리핑의 근거 데이터가 누락·중복·시점 오류 없이 사용되게 한다. |
| 입력 | 야간 선물·환율·글로벌 지수, 뉴스 헤드라인, 테마 매핑 |
| 처리 | 필수 필드, 시점, 출처, 거래일, 중복, 누락을 검증한다. |
| 출력 | 사용 가능 입력, 검증 상태, 실패 사유 |
| 예외 | 검증 실패 시 테마 순위와 브리핑을 만들지 않는다. |
| 완료 기준 | 잘못된 시점·중복·필수 필드 누락 입력이 차단된다. |

## 3. 전략 및 백테스트 기능

### F-B01. 전략 빌더

| 항목 | 정의 |
|---|---|
| 목적 | 사용자가 재현 가능한 전략 조건을 정의한다. |
| 입력 | 패턴 선택, AND/OR, 청산 규칙, 시장, 기간, 거래대금 하한, 시총 그룹 |
| 처리 | 필수값·형식·단위를 검증하고 전략 설정을 저장 가능한 구조로 변환한다. |
| 출력 | 유효한 전략 설정과 실행 가능 여부 |
| 화면 | Strategy Builder의 Buy conditions / Sell & exit rules / Universe & period 카드 |
| 예외 | 날짜 형식 오류, 기간 역전, 허용되지 않은 청산값은 입력 단계에서 설명과 함께 차단한다. |

입력 단위는 다음으로 고정한다.

| 값 | 단위·형식 |
|---|---|
| 날짜 | `YYYY-MM-DD` |
| 거래대금 | KRW 정수 |
| 퍼센트 | 단일 퍼센트 단위(예: `-5`는 -5%) |
| 보유 기간 | 거래일 수 정수 |
| 미사용 Trailing stop | `null` |

### F-B02. 패턴 신호 생성

| 항목 | 정의 |
|---|---|
| 목적 | 고정된 기술적 패턴을 날짜별 매수 신호로 계산한다. |
| 대상 | ma_cross_5_20, breakout_20d, breakout_vol, rsi_rebound, bb_lower_recover 및 후순위 패턴 |
| 입력 | 종목별 OHLCV와 해당일까지의 지표 |
| 출력 | 날짜별 bool 매수 신호 |
| 제약 | UI에서 파라미터를 최적화하거나 그리드 서치하지 않는다. |
| 검증 | 기준일 이후 데이터를 잘라도 앞 구간 신호가 동일해야 한다. |

### F-B03. 백테스트 체결·청산·비용

| 항목 | 정의 |
|---|---|
| 목적 | 현실적인 체결 제약과 비용을 반영한 거래 내역을 만든다. |
| 진입 | 신호일 다음 거래일 시가. 상한가(+30%)면 스킵 사유를 기록한다. |
| 보유 | 종목당 하나의 포지션만 허용하며 보유 중 신규 신호는 무시한다. |
| 청산 | 손절·익절·시간 청산 중 먼저 충족한 조건을 다음 거래일 시가에 체결한다. 하한가면 다음 날 재시도한다. |
| 비용 | 왕복 기본 0.30%를 손익에서 차감하고 실행 설정에 기록한다. |
| 출력 | 거래별 진입/청산, 수익률, 단순보유 수익률, 초과수익, 스킵·체결 제약 정보 |

### F-B04. 전략 B 조건부 분석

| 항목 | 정의 |
|---|---|
| 목적 | 전일 확정 VWAP_20과 야간 테마 가중치가 결합된 조건의 과거 성과를 분석한다. |
| 입력 | 전일 확정 VWAP_20, 야간 테마 가중치, 일봉 데이터, 고정 진입·청산 규칙 |
| 출력 | 기간, 거래 수, 승률, 기대손익비, 샤프, MDD, 비용, 제외 거래 수 |
| 제약 | 장중 09:10~09:40 체결 신호나 국내 주식 분봉 체결 분석을 생성하지 않는다. |

### F-B05. 집계 및 3중 검증

| 항목 | 정의 |
|---|---|
| 목적 | 우연한 성과를 걸러내고 조건별 성과를 비교한다. |
| 집계 | 국면 × 시장 × 시총 그룹별 거래 수, 승률, 평균/중앙값 손익, 초과수익, 손익비 |
| 표본 규칙 | 300건 미만 셀은 `Sample insufficient`로 표시하고 결론·분석 대상 선정에 사용하지 않는다. |
| 검증 | 전반/후반 기간 분할, Benjamini-Hochberg FDR(q ≤ 0.10), 1,000회 무작위 벤치마크 |
| 출력 | 검증 통과/탈락 상태, 근거 지표, 제한 사항 |

## 4. 실행 API 및 화면 기능

### F-X01. 비동기 실행

| 항목 | 정의 |
|---|---|
| 목적 | 긴 분석을 UI가 멈추지 않는 방식으로 실행한다. |
| 요청 | 전략 조건 JSON |
| 응답 | 고유 `run_id` |
| 후속 조회 | `run_id`로 상태, 진행률, 결과, 오류, 취소 상태를 조회한다. |
| 제약 | Unity Web은 Python 로컬 파일을 직접 읽지 않고 API JSON만 사용한다. |
| 완료 기준 | 요청부터 결과까지 모든 화면 데이터가 동일한 `run_id`로 연결된다. |

### F-X02. 실행 진행 화면

| 항목 | 정의 |
|---|---|
| 표시 | 현재 단계, 처리 종목 수/전체 수, 경과 시간, 서버 제공 시 예상 남은 시간 |
| 단계 | 필터 → 로드 → 지표 → 신호·체결 → 국면 결합 → 집계 → 저장 |
| 상태 | running, completed, failed, cancelled |
| 사용자 행동 | 취소, 완료 후 결과 보기, 실패 후 전략 조건으로 복귀 또는 재시도 |
| 제약 | 화면 애니메이션으로 완료·진행률을 임의 추정하지 않는다. |

### F-X03. Results

| 항목 | 정의 |
|---|---|
| 목적 | 전략 전체의 성과·위험·검증 상태를 한 화면에서 비교한다. |
| 표시 | 전략명, 기간, 유니버스, 비용, 거래 수, 승률, 평균/중앙값 손익, 손익비, 초과수익, 검증 상태 |
| 시각화 | 국면별 표, 시장×시총 히트맵, 손익 분포, 기간 분할 비교 |
| 이동 | Stock Detail, AI Report, Strategy Builder 수정 |
| 빈 상태 | 결과 없음, 데이터 없음, 표본 부족, 실패·취소를 구분해 원인과 다음 행동을 제공한다. |

### F-X04. Stock Detail

| 항목 | 정의 |
|---|---|
| 목적 | 특정 종목의 거래 근거와 성과를 확인한다. |
| 입력 | `run_id`, ticker |
| 표시 | 가격·이동평균·국면 배경, 진입·청산 마커, 자산곡선과 단순보유 비교, 거래 테이블, 표본 수 |
| 제약 | 성과가 좋은 종목을 추천처럼 표시하지 않는다. |

### F-X05. AI Report

| 항목 | 정의 |
|---|---|
| 목적 | 실행 결과와 시장 조건을 읽기 쉬운 문장으로 설명한다. |
| 입력 | 동일 `run_id`의 집계·국면·검증·브리핑 근거 JSON |
| 출력 | 한국어 해설, 표본·데이터 한계, 고지 |
| 검증 | 출력 숫자를 입력 JSON과 비교한다. 불일치·권유 표현이 있으면 경고 또는 템플릿으로 대체한다. |
| 제약 | AI는 수치·순위·국면·매수 결정을 새로 만들지 않는다. |

### F-X06. Morning Briefing

| 항목 | 정의 |
|---|---|
| 목적 | 야간 시장 변화와 국내 조건부 분석을 한 흐름으로 보여준다. |
| 표시 순서 | 야간 시장 상태 → 충격 근거 → 테마 분석 → 조건부 과거 성과 → 한계·고지 |
| 출력 | 충격 점수, 관련 이벤트, 테마 상위 3개, 분석 대상, 검증 상태 |
| 예외 | 야간·뉴스·테마 입력이 없거나 검증 실패 시 브리핑 대신 원인과 상태를 표시한다. |

## 5. 유사 패턴 탐색 기능

### F-PAT01. 과거 유사 사례 검색

| 항목 | 정의 |
|---|---|
| 목적 | 현재 관측 구간과 모양이 유사한 과거 구간을 찾아 비교한다. |
| 입력 | ticker, 관측 기간, 데이터 기준일 |
| 처리 | 기준일 이전의 과거 구간만 검색하고 공통 축으로 정규화한다. |
| 출력 | 과거 사례, 비교 기간, 유사도, 정규화 방식, 과거 후속 실제 데이터 |
| 제약 | 기준일 이후 데이터를 검색·표시하지 않으며, 미래 가격·수익률 예측값을 만들지 않는다. |

| 항목 | 정의 |
|---|---|

| 시각 구분 | 현재 관측, 유사 과거, 과거 후속 실제 결과를 색·선 종류·범례·라벨로 분리 |
| 필수 메타데이터 | 기간, 유사도, 정규화 방식, 데이터 기준일 |
| 금지 표현 | Forecast, 확정적 상승/하락, 매수·매도 권유 |

## 6. 공통 상태와 오류 처리

| 상태 | 발생 조건 | UI 처리 |
|---|---|---|
| Loading | 요청 또는 분석 진행 중 | 실제 진행 정보와 취소 행동 표시 |
| Empty | 아직 실행 결과가 없음 | 전략 생성 또는 이전 화면 이동 제공 |
| Sample insufficient | 거래 수 300건 미만 | 표본 수와 분석 제한 표시 |
| Validation failed | 데이터·입력·계약 검증 실패 | 원인, 문제 필드, 수정/재시도 행동 표시 |
| Network/server error | 연결 또는 서버 작업 실패 | 사람이 이해할 수 있는 오류와 재시도 제공 |
| Cancelled | 사용자가 실행을 취소함 | 취소 완료와 결과 생성 여부 표시 |

## 7. 디자인·접근성 적용 규칙

- Canvas 기준은 1920×1080 데스크톱이며, Header 120 / Sidebar 360 / Content Area 구조를 따른다.
- 카드·헤더·사이드바는 다크 표면, 입력·일반 버튼은 한 단계 밝은 표면, 주요 행동·선택은 민트로 표현한다.
- 모든 버튼은 기본·hover·pressed·focus·disabled 상태를 제공하고 최소 44×44 클릭 영역을 확보한다.
- 키보드로 모든 입력·탐색·실행을 수행할 수 있어야 한다.
- 색상만으로 선택·성공·실패·표본 부족을 전달하지 않는다.
- 모든 결과 화면에 `Historical analysis — not investment advice.`를 표시한다.

## 8. 기능별 검증 매핑

| 기능 | 핵심 검증 |
|---|---|
| 데이터·국면 | 미래참조 방지, 품질·유니버스 검증 |
| 신호·체결 | 다음 거래일 시가, 상/하한가 스킵, 비용 반영 |
| 집계·검증 | 기간 분할, FDR, 무작위 벤치마크 재현성 |
| 야간·브리핑 | 입력 계약, 결측 시 발행 차단, 동일 입력 재현성 |
| 실행 API | `run_id` 일관성, 상태·취소·오류 응답 |
| 유사 패턴 | 기준일 이후 데이터 차단, 정규화 메타데이터, 예측과의 문구 분리 |
| AI 보고서 | 수치 대조, 권유 표현 차단, 템플릿 폴백 |
