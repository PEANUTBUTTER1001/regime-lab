## 2. G2 반영용 책임·파일·의존 표

경로 접두어는 `ingest/src/regime_ingest/`다. PR #21에 이미 있는 파일을 기준으로 하며, 동일 이름의 병행 구현을 만들지 않는다.

| 역할 | 파일 | 책임 / 허용 I/O |
|---|---|---|
| 진입 | `cli.py` | 인자 검증·출력. 시계와 기본 종료일 결정은 조립에 위임 |
| 조립 | `app.py` | 환경변수 키·시계·실행 ID·구현체 연결. 네트워크/저장소 생성 |
| 유스케이스 | `collect.py` | 수집 창·재시도 결과·정규화·저장 확정 순서. 주입된 협력자만 사용 |
| 도메인 | `timing.py` | 순방향/소급 시각, 날짜 창 분할. 시계·휴장일 네트워크 조회 없음 |
| 도메인 | `normalize.py` | 스키마·식별자 검증·메타데이터 정규화·native 종목 연결 |
| 도메인 | `dedup.py` | 접수번호 멱등·관측 버전·정정 후보. 파일/DB/HTTP 접근 없음 |
| 인프라 | `sources/opendart.py` | HTTP, 오류 분류, 페이지·요청 한도, 비밀 가림 |
| 인프라 | `store.py` | 원본 목록 메타데이터·Parquet·SQLite·잠금·공개 시점 일관성 |

공개 진입점은 CLI `run --source opendart`, `backfill --source opendart --from ... --to ...`, `status`다. 기존 engine/API 공개 모듈 목록은 늘리지 않는다. 데이터 소비 계약은 아래 스키마와 확정된 문서/coverage 스냅샷이다. API가 `regime_ingest`를 직접 import하는 것은 허용하지 않는다.

G2에서 확인할 의존성:

- R1: PR #21 `collect.py`는 `Store`, `OpenDartList`, 오류 클래스를 인프라에서 import한다. 구조 지도에 파일을 더하는 것만으로 이 의존이 해소되지는 않는다. 실제로 필요한 HTTP 테스트 대역·저장 실패 대역을 위한 좁은 포트를 정의하거나 기존 결합을 명시적인 예외로 검토해야 한다. 에이전트가 새 예외 승인을 대신하지 않는다.
- R2/R3: 조립에서 시계·환경변수·파일 경로·구현체를 연결한다. 도메인 함수는 입력에만 의존하고 호출 시각을 스스로 읽지 않는다. `cli.py`의 OS 로컬 날짜 기본값도 KST 조립 시계와 일치시킨다.
- R7: 소스는 하나이므로 범용 플러그인 레지스트리·추상 수집 프레임워크를 도입하지 않는다. 테스트 대역이 실제 필요한 작은 경계만 둔다.
- `<ext_store>`는 `data/`, `multi_tables_db/`, 저장소의 추적 파일 영역과 겹치지 않도록 해석된 절대 경로를 검사한다. 원본 폴더 안쪽이나 원본 폴더를 포함하는 상위 폴더도 거부한다. Parquet만 읽고 `regime.duckdb`는 열지 않는다.

## 3. 문서 식별·필드 계약

[계획 §5](plan/03-04-external-crawling-automation.md#5-정규화-스키마-제안)의 필드를 유지한다. `schema_version=1`을 문서 데이터셋 manifest에 기록하고, 정규화·시각 정책 버전도 manifest에 고정한다. 정책을 바꿀 때 과거 행을 덮어쓰지 않는다. PR #21에는 아직 manifest 버전이 없으므로 추가 작업이다.

| 필드 | 공시 규칙 |
|---|---|
| `doc_id` | `opendart:<rcept_no>`; `rcept_no`는 정확히 숫자 14자리. 다른 접수번호는 다른 문서 |
| `version` | 동일 접수번호의 실제 관측 내용 변경 순서, 1부터 시작. 같은 내용 재수집 시 증가하지 않음 |
| `published_at` | `YYYY-MM-DD`, 가짜 00:00 접수 시각을 넣지 않음 |
| `published_at_basis`, `time_precision` | `dart_receipt_date`, `date_only` |
| `first_seen_at` | 해당 버전을 최초 관측한 offset 포함 ISO 시각. 재수집으로 변경하지 않음 |
| `available_at` | 아래 시각 계약. 날짜만으로 실제 보유 여부를 주장하지 않음 |
| `backfilled` | 최초 역사 소급 수집 여부. 조회 모드 바뀜만으로 기존 문서의 의미를 바꾸지 않음 |
| `modified_at` | 출처가 주지 않으면 null. 수집 시각으로 대체하지 않음 |
| `license_scope`, `summary`, `body_ref` | `metadata_only`, null, null |
| `tickers` | `stock_code`가 `^[0-9A-Z]{6}$`일 때 native 연결 근거. 코드 숫자 변환 금지, 선행 0 보존 |
| `ticker_status` | 빈 코드 `none`; 형식 오류는 오류/격리; 상충 매핑은 `ambiguous`. 단지 값이 있다는 이유로 `resolved`로 두지 않음 |
| `content_hash` | 정규화한 의미 필드의 지문. 조회일·페이지·run_id는 제외. 회사코드·시장·접수일 등 의미 필드 변경도 포함 |
| `cluster_id` | 공시 초기값 null. 정정 후보나 동일 제목으로 곧바로 같은 사건으로 합치지 않음 |

native 연결은 출처가 주장한 코드 연결이며, 당시 투자 가능 유니버스에 속한다는 판정이 아니다. 현재 종목 마스터에 없다고 역사 공시를 삭제하지 않는다. 회사코드 8자리, 접수일 유효성, 조회 창/시장 일치도 검사한다. 잘못된 행은 저장 개수에서 빠졌다는 이유로 정상 수집으로 간주하지 않는다.

새 접수번호의 정정 공시는 `version=1`인 독립 문서다. `amends_candidate_doc_id`·`amends_basis`는 후보만 나타낸다. 원공시를 확정하는 출처 근거가 없는 동안 `amends_doc_id`는 설정하지 않는다. 접수번호 자신·나중 접수번호·다른 회사는 후보에서 제외한다. 여러 후보가 있으면 확정하지 않고 모호성을 유지한다. 제목·기업명으로 원문에 없는 정정 관계를 만들어내지 않는다.

## 4. 시각 계약: 관측 재현과 역사 가정

두 조회 모드는 호출자가 명시적으로 선택하고 결과/스냅샷에 기록한다. 기본값은 `observed`다.

| 모드 | 시각 T에서 허용하는 문서 버전 | 용도와 제한 |
|---|---|---|
| `observed` | `first_seen_at <= T` **그리고** `available_at <= T` | 실제 수집기 보유 시점 재현, 순방향 브리핑·분봉 입력 |
| `historical_assumed` | 승인된 소급 정책에 따라 `available_at <= T` | 날짜 단위 일봉 연구만. 당시 실제 보유 증거가 아니며 순방향 성과와 분리 보고 |

1. 순방향 첫 버전: `available_at = first_seen_at`.
2. 최초 소급 버전: 접수일 **다음 달력일 00:00 KST**를 보수적 일봉 연결 기준으로 사용한다. 그날이 휴장일이면 가격 데이터의 다음 실제 거래일 첫 봉에 연결한다. 휴장일을 평일 규칙만으로 추정하지 않는다.
3. **같은 접수번호의 내용 변경 버전:** 출처에서 변경의 과거 시각을 증명하지 못하면 `available_at = max(first_seen_at, 직전 버전.available_at)`이다. 소급 모드로 재조회했어도 새 내용을 원래 접수일로 되돌리지 않는다. 원래 버전과 first_seen_at은 보존한다.
4. KST로 정규화한 timezone-aware 시각끼리 비교한다. naive 시각은 거부한다. 시스템 시계가 뒤로 간 관측은 격리하거나 직전 관측보다 앞선 유효 시각을 부여하지 않는다.
5. 문서를 연결할 첫 봉은 `bar.start > available_at`. 정확히 09:00에 관측된 자료는 이미 09:00에 시작한 봉에 넣지 않는다. `bar.end`나 달력 날짜로 대체하지 않는다. 분봉에는 날짜 단위 역사 소급분을 쓰지 않는다.
6. 동일 doc_id에서 T에 허용되는 버전 중 최신을 선택한다. 정정 후보·종목/사건 연결도 T까지 알 수 있었던 관계만 사용한다. 나중 정정 때문에 과거 문서 행이나 스냅샷을 고치지 않는다.
7. 스냅샷에는 cutoff, 조회 모드, 정책/스키마 버전, `(doc_id, version, content_hash)` 목록, 그 당시 coverage를 고정한다. 현재 coverage·현재 전역 cluster_id로 옛 스냅샷을 재구성하지 않는다.

역사 소급의 한계: 처음 받아온 목록 자체가 과거에 어떻게 바뀌었는지 증명할 수 없다. `historical_assumed`는 이 한계를 제거하지 않는다. 정정 관계나 본문 내용을 복원했다는 주장도 하지 않는다. 날짜 기반 정책은 실측한 공개 시각이 아니다.

## 5. 페이지·실패·저장 계약

- 목록 호출은 Y/K 별도, `page_count=100`, `last_reprt_at=N`, 기본은 모든 공시 유형이다. n8n의 B/I 선별·건수 상한을 5년 수집의 모집단으로 재사용하지 않는다.
- 013만 정상 0건이다. 000이지만 list/페이지 필드가 없거나 잘못되면 실패다. 마지막 페이지까지 누적 건수·고유 접수번호 수·total_count를 대조한다. 수집 중 목록 변동은 재확인 창이나 불완전 상태로 기록한다.
- 020·429·인증 오류·재시도 소진은 빈 정상 결과가 아니다. 모든 재시도 **직전** 일 한도를 검사하고 요청 횟수에 포함한다. `Retry-After`를 따르고 인증 오류는 무한 재시도하지 않는다. DART 서버 응답 문구도 키/개인정보가 섞였을 수 있으므로 그대로 기록하지 않는다.
- 유효하지 않은 행이 하나라도 남은 창은 완료 커서를 넘기지 않는다. `partial`/`gap`과 원인 집계를 남겨 재처리할 수 있어야 한다. 오류의 원자료가 공개 로그·Git fixture로 흘러가지 않게 한다.
- Parquet 직접 쓰기와 SQLite commit은 하나의 원자적 트랜잭션이 아니다. 임시 파일·확정 manifest 또는 동등한 복구 저널을 사용해 소비자는 확정된 파일만 읽게 한다. 파일 쓰기/rename/DB commit 어느 경계에서 끊겨도 재실행 후 `(doc_id, version)` 중복과 가리키는 파일 유실이 없어야 한다.
- 현재 PR의 일×시장 coverage는 역사 소급 창 검증에 사용할 수 있지만, 5분 순방향 수집의 시간 공백을 뜻하지 않는다. 순방향은 조회/관측 종료시각을 함께 남기고 이후 시간까지 정상으로 채우지 않는다. 과거 snapshot에 필요한 coverage 이력을 덮어쓰지 않는다.
- 저장 경로 오류·디스크 용량 부족·권한 오류를 `skipped`(중복 실행)로 처리하지 않는다. 실제 잠금 충돌만 skipped다. 잠금 해제와 실패 기록도 실패 시점에 검증한다.
