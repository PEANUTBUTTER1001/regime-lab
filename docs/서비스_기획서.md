# 서비스 기획서

| 항목 | 내용 |
|---|---|
| 서비스명 | 과거 패턴 기반 주식 분석·백테스팅 서비스 |
| 문서 목적 | 서비스 목표, 사용자 경험, 제공 가치, 범위를 팀이 같은 기준으로 이해한다. |

| 서비스 성격 | 과거 데이터 분석 및 학습 도구. 투자 권유·주문 서비스가 아님. |

---

## 1. 서비스 개요

본 서비스는 사용자가 알려진 기술적 패턴과 청산 조건을 조합해 국내 주식의 과거 데이터를 검증하고, 시장 환경별 성과와 한계를 확인할 수 있게 하는 웹 분석 서비스다. 야간 시장·뉴스·테마 입력이 있을 때는 그 근거를 바탕으로 개장 전 시장 브리핑을 제공한다.

서비스의 핵심은 “어떤 종목을 사야 하는가”가 아니라, **어떤 조건이 어떤 과거 환경에서 얼마나 일관되게 작동했는가**를 사용자가 재현 가능하게 탐색하도록 돕는 데 있다.

## 2. 문제 정의

| 사용자 문제 | 기존의 어려움 | 서비스의 대응 |
|---|---|---|
| 전략 검증의 어려움 | 조건검색 결과나 단순 수익률만 보고 성과를 판단하기 쉽다. | 비용·체결 제약·초과수익·시장 국면을 포함한 백테스트를 제공한다. |
| 시장 환경 차이 | 같은 패턴도 상승·하락·횡보 국면에서 다르게 작동한다. | 시장·종목 국면, 시장 구분, 시총 그룹별 성과를 분해한다. |
| 미래참조 및 과적합 위험 | 미래 정보를 섞거나 좋은 구간만 보고 전략을 판단할 수 있다. | 시점 기준 계산, 기간 분할, FDR, 무작위 벤치마크를 적용한다. |
| 복잡한 야간 정보 | 글로벌 시장·뉴스를 국내 시장과 연결해 해석하기 어렵다. | 충격 근거와 테마 가중치를 조건부 과거 성과와 함께 제시한다. |
| 분석 결과 해석 | 수치가 많아도 일반 사용자는 의미를 이해하기 어렵다. | LLM이 검증된 입력 수치만 해설하고, 표본·한계·고지를 함께 보여준다. |

## 3. 목표 사용자와 핵심 과업

| 사용자 | 상황 | 핵심 과업 | 기대 결과 |
|---|---|---|---|
| 일반 사용자 | 매매 기법을 검증하고 싶다. | 조건을 선택하고 결과·한계를 읽는다. | 전략을 맹신하지 않고 근거를 비교한다. |
| 학습자 | 기술적 분석과 백테스트를 학습한다. | 패턴·청산·시장 환경이 성과에 미치는 영향을 본다. | 분석 지표와 검증 절차를 이해한다. |
| 평가자 | 데이터·AI 프로젝트의 타당성을 평가한다. | 누수 방지, 재현성, AI 경계를 확인한다. | 신뢰 가능한 구현 근거를 확인한다. |
| 팀원 | 기능을 개발·검수한다. | 같은 실행 결과와 문서를 기준으로 작업한다. | 화면·API·데이터 계약의 불일치를 줄인다. |

## 4. 제품 비전과 가치 제안

### 비전

**복잡한 시장 정보를 빠른 판단의 근거가 아니라, 검증 가능한 분석의 출발점으로 바꾼다.**

### 핵심 가치

1. **재현 가능성** — 같은 데이터·설정·시드라면 같은 결과를 확인할 수 있다.
2. **맥락 있는 성과** — 전체 수익률뿐 아니라 국면·시장·시총 그룹·표본 수를 함께 본다.
3. **과장 없는 AI** — AI는 설명을 돕고, 수치 계산·순위·추천을 대신하지 않는다.
4. **신뢰할 수 있는 시각화** — 시각적으로 매력적이되, 차트·표·브리핑이 데이터 근거와 한계를 숨기지 않는다.

## 5. 서비스 경험 원칙

| 원칙 | 제품 적용 |
|---|---|
| 근거 우선 | 모든 핵심 성과에 기간·거래 수·계산 기준·데이터 상태를 함께 표시한다. |
| 비권유 | 종목은 `Analysis target`으로 표시하며 목표가·비중·주문·매수 지시를 제공하지 않는다. |
| 과거와 예측 분리 | 유사 패턴의 이후 움직임은 과거 실제 결과로만 표시하고 예측처럼 보이지 않게 한다. |
| 실패도 정보 | 데이터 부족·표본 부족·검증 실패·네트워크 실패를 숨기지 않고 원인과 다음 행동을 제공한다. |
| 차분한 집중 | 다크 테마와 민트 강조는 사용자의 다음 행동과 분석 근거를 명확히 하는 데만 사용한다. |

## 6. 핵심 사용자 흐름

```text
로그인 UI
  → Strategy Builder
  → 백테스트 실행 요청
  → 실행 진행 확인
  → Results
  ├→ Stock Detail
  ├→ AI Report
  └→ 전략 조건 수정 후 재실행

Morning Briefing
  → 야간 시장 상태
  → 충격 근거와 테마 분석
  → 조건부 과거 성과
  → 한계·비권유 고지
```

- 로그인과 가입은 현재 UI 흐름만 제공하며, 실제 인증·계정 저장은 이후 단계다.
- 긴 분석은 브라우저가 직접 실행하지 않는다. 실행 요청 후 `run_id`로 진행 상태와 결과를 조회한다.
- 유사 패턴 비교는 Stock Detail에서 확장 가능한 탐색 흐름이며, 현재 구간과 과거 사례를 비교한다.

## 7. 서비스 구성

| 영역 | 사용자 가치 | 대표 산출물 |
|---|---|---|
| Strategy Builder | 전략 조건을 명확히 정의한다. | 조건 조합, 기간·유니버스 설정, 실행 전 요약 |
| Backtest Progress | 분석이 실제로 진행 중임을 신뢰할 수 있게 한다. | 단계, 처리 수, 경과 시간, 실패·취소 상태 |
| Results | 전략 전체의 성과와 신뢰도를 파악한다. | 요약 카드, 국면별 표, 히트맵, 분포, 기간 분할 |
| Stock Detail | 개별 종목의 거래 근거와 한계를 확인한다. | 가격 차트, 진입·청산, 거래 내역, 자산곡선 |
| AI Report | 검증된 수치를 자연어로 이해한다. | 국면 설명, 성과 해설, 한계 및 개선 후보 |
| Morning Briefing | 야간 변화와 국내 분석 조건을 연결한다. | 시장 상태, 충격 근거, 테마 분석, 조건부 성과 |
| Similar Pattern Explorer | 현재 관측과 과거 유사 사례를 비교한다. | 정규화 차트, 유사도, 과거 후속 실제 데이터 |

## 8. 제공 범위와 제외 범위

| 구분 | 포함 | 제외 |
|---|---|---|
| 분석 데이터 | 국내 주식 일봉, 시장·종목 국면, 야간 시장·뉴스·테마의 검증된 입력 | 국내 주식 장중 체결 분석, 1분봉 기반 분석 |
| 전략 | 고정 파라미터 패턴, 청산 규칙, 비용·체결 제약, 검증 | 사용자 주도 파라미터 최적화·그리드 서치 |
| AI | 결과 해설, 자연어 전략 변환, 제한된 개선 후보 | 가격 예측, 신호 결정, 종목 추천 |
| 외부 연동 | 허가된 샘플/표준 입력, 분석 API | 증권 주문, 실시간 유료 데이터 계약, 자동 알림 발송 |
| 사용자 계정 | 로그인·가입 UI 흐름 | 실제 인증, 계정·비밀번호 저장, 결제·구독 |

## 9. 성공 기준

서비스 성공은 수익률이나 예측 정확도를 약속하는 것으로 평가하지 않는다. 아래 기준으로 확인한다.

| 영역 | 성공 기준 |
|---|---|
| 신뢰성 | 동일한 실행 설정에서 동일 결과를 재현하고, 미래참조 방지 테스트를 통과한다. |
| 분석 품질 | 핵심 결과에 거래 수·비용·체결 제약·검증 상태가 포함된다. |
| 이해 가능성 | 사용자가 결과 화면에서 전략 조건, 기간, 주요 성과, 표본 부족 여부를 확인할 수 있다. |
| UI 품질 | 실행·완료·실패·빈 결과·취소 상태를 혼동 없이 이해하고 다음 행동을 선택할 수 있다. |
| 안전성 | 모든 화면에서 비권유 고지가 보이고, AI가 입력에 없는 수치나 권유 문구를 표시하지 않는다. |

## 10. 단계별 출시 우선순위

| 단계 | 목표 | 핵심 결과 |
|---|---|---|
| MVP | 일봉 백테스트와 검증 가능한 결과 화면 | Strategy Builder, Results, 비용·체결·국면·기간 분할 |
| 분석 확장 | 야간 시장·테마를 분석 근거로 연결 | Morning Briefing, 충격·테마 입력 검증 |
| 탐색 확장 | 개별 사례의 이해를 높인다. | Stock Detail, 유사 패턴 과거 사례 비교 |
| 선택 기능 | 해석·생산성을 높인다. | AI 보고서, 자연어 전략 변환, ML 필터 |

일정이 부족하면 자연어 전략 변환, 개선 루프, ML 필터, 유사 패턴 3D, 후순위 패턴 순으로 축소한다. 미래참조 방지, 비용 반영, 핵심 성과 집계, 비권유 고지, 데이터 검증 실패 처리는 축소하지 않는다.

## 11. 운영·정책 원칙

- 원본 시세, 뉴스 원문, 비밀키는 저장소에 커밋하지 않는다.
- 야간·뉴스 입력의 출처·시점·중복·누락을 확인하지 못하면 브리핑을 발행하지 않는다.
- 데이터 부족, 표본 부족, 검증 탈락은 사용자에게 불리한 정보가 아니라 분석 결과의 일부로 표시한다.
- 결과는 과거 데이터의 조건부 분석이며 미래 성과를 보장하지 않는다.
