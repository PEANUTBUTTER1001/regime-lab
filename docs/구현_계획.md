## 1. 구현 원칙

1. **미래참조 금지가 최우선이다.** 모든 모듈은 t일 계산에 t일까지의 값만 쓰고, 이를 `test_lookahead`로 검증한다.
2. **수치 파라미터는 설정 파일에 둔다.** 코드에 상수를 넣지 않고, 실행마다 설정 전체를 메타데이터로 저장한다.
3. **데이터 소스를 섞지 않는다.** 본 데이터는 `store/`, `kor_price`는 워밍업 보정, `kor_indicators`는 테스트 참조값 용도로만 쓴다.
4. **분석 엔진은 UI·API와 독립이다.** 1단계 엔진은 CLI로 실행 가능해야 하고, API는 엔진을 호출만 한다.
5. **제외 범위(§8 추후 과제)는 인터페이스 자리만 두고 구현하지 않는다.** 해당 화면·API는 `Data unavailable` 상태를 반환한다.

## 4. 파라미터 정의 (`config/default.yaml`)

### 4.1 핵심 패턴 5종 (A7)

신호일 t 기준이며 모든 값은 t일까지 확정된 데이터만 사용한다.

| 패턴 | 매수 신호 조건 | 참조값 대조 (`kor_indicators`) |
|---|---|---|
| `ma_cross_5_20` | SMA5(t-1) ≤ SMA20(t-1) 이고 SMA5(t) > SMA20(t) | `MA_5`, `MA_20` |
| `breakout_20d` | 종가(t) > 직전 20거래일(t-20 ~ t-1) 고가의 최댓값 | — (수기 계산) |
| `breakout_vol` | `breakout_20d` 조건 충족 이고 거래량(t) ≥ 직전 20거래일 평균 거래량 × 2.0 | — (수기 계산) |
| `rsi_rebound` | RSI14(t-1) < 30 이고 RSI14(t) ≥ 30. RSI는 14일 단순평균 방식 (S5 대조 결과, A7-1) | `RSI_14` |
| `bb_lower_recover` | 종가(t-1) < 볼린저 하단(t-1) 이고 종가(t) ≥ 볼린저 하단(t). 볼린저 20일, 2σ | `BB_Lower_20` 또는 `BB_Lower_20_ddof` |

- 참조 테이블의 RSI 평활 방식과 볼린저 표준편차 방식(ddof)은 1단계 S5에서 대조해 일치하는 쪽으로 고정하고 설정에 기록한다.
- 복수 패턴은 AND/OR로 결합하며 파라미터는 UI에서 바꿀 수 없다(FR-P4).

### 6.4 API 계약 (초안)

| 메서드·경로 | 용도 | 주요 응답 |
|---|---|---|
| `GET /api/meta` | 빌더 초기값 | 데이터 기준일, 패턴 목록, 청산 기본값·허용 범위, 시장·시총 그룹, 지표 정의, 고지 |
| `POST /api/universe/preview` | 예상 대상 종목 수 (design.md §6.2) | 입력 필터(시장·기간·거래대금 하한·시총 그룹)를 통과하는 종목 수·종목·일 수. 백테스트는 실행하지 않음 |
| `POST /api/runs` | 실행 요청 | `202 {run_id}` / `422` 필드별 오류 / `409` 실행 중(E4) |
| `GET /api/runs` | 최근 실행 목록 | 새로고침 후 복구용 (NFR-13) |
| `GET /api/runs/{run_id}` | 상태 | `status`(queued·running·completed·failed·cancelled), `stage`, `stages`, `processed`, `total`, `elapsed_sec`, `error` |
| `POST /api/runs/{run_id}/cancel` | 취소 | 취소 수락 여부, 결과 미생성 안내 |
| `GET /api/runs/{run_id}/result` | 결과 | 요약·지표 정의, 검증(m 포함), 셀 집계(시장/종목 국면), 손익 분포, 분할 비교, 종목별 표본 표, 고지 |
| `GET /api/runs/{run_id}/stocks/{ticker}` | 종목 상세 | 가격·이동평균·국면 구간, 거래 마커·표, 종목 자산곡선과 단순 보유 비교, 표본 수 |
| `POST /api/runs/{run_id}/report` | AI 보고서 | `status`(verified·fallback), 본문, 경고, 공급사·모델, 캐시 여부, 고지 |
| `GET/PUT/DELETE /api/llm/config` | AI 보고서 모델명·키 (E10 잠정) | `{provider, model, key_set, key_hint(마지막 4자리), source(ui·env·none)}`. 키 원문은 응답하지 않음. PUT·DELETE는 루프백 요청만(`403 local_only`) |
| `GET /api/briefing` | Morning Briefing | `status: data_unavailable`, 사유 |

- 오류 응답은 공통 형식 `{code, message, detail, retryable}`로 통일해, 화면 상태(§7.4)와 1:1로 대응시킨다.
- 응답 스키마는 FastAPI가 만드는 OpenAPI(`/openapi.json`)를 계약의 기준으로 삼는다. Unity 이관(T-8) 시 C# 모델도 이 문서에서 만든다.

### 6.5 LLM 보고서 규칙

- 입력은 같은 `run_id`의 구조화 JSON(요약·셀·검증·표본 부족·데이터 한계)만 사용한다. 원본 시세·개인정보는 보내지 않는다.
- 프롬프트는 수치 생성·순위 변경·투자 권유를 금지하고, 표본 부족·한계를 반드시 쓰도록 요구한다(FR-L2).
- 숫자 검증: 출력의 모든 수치(%, %p, 건, 소수)를 추출해 입력 JSON 값과 표시 반올림 오차 안에서 대조한다. 입력에 없는 수치가 있으면 거부하고 템플릿으로 대체한다(FR-L3, NFR-7).
- 권유 표현(매수·매도 추천, 목표가, 비중, 유망, 사세요, Buy, Top pick 등)이 있으면 거부한다.
- 캐시 키: 전략·데이터 기준일·설정 해시·프롬프트 버전·공급사·모델(FR-L4). 캐시 파일에는 키가 들어가지 않는다.
- 프롬프트 `report-v2`(2026-09-23, `api/src/regime_api/llm/prompt.py`): 근거 수치에 한국어 이름(`*_ko`: 패턴·결합·시장·시총·분할 판정·통과 여부·분석 대상·셀별 국면/시장/시총)과 충분 셀 수·양수/음수 셀 수를 넣고, 규칙에 천 단위 쉼표·국면별 성과 1~2문장(요약 끝, 순위 금지)·코드값/필드명/true·false 금지·마크다운 강조 금지를 추가했다. 형식은 3단(요약·검증 결과·한계) 유지. 템플릿 보고서(`template.py`)도 같은 국면별 성과 문장을 쓴다. 화면(`report.js`)은 남은 백틱·굵게·목록 기호를 지운다. 버전이 바뀌어 v1 캐시는 쓰지 않는다.
- 모델명·키는 환경변수 또는 ⚙ 설정 화면(E10 잠정)으로 받는다. 화면 입력 키는 서버 메모리에만 두며, 공급사 오류 문구에 섞인 키 조각은 `[redacted]`로 가린다.
- 응답에는 `verified` 또는 `fallback` 상태를 명시한다. 화면은 `fallback`을 정상 AI 해설처럼 보이게 표시하지 않는다.

### 7.4 상태·접근성 기준

- 상태: Loading, Empty, Sample insufficient, Validation failed, Network/server error, Cancelled (design.md §8.2). API 공통 오류 형식(§6.4)의 `code`로 상태를 고른다. 모든 상태에 원인·복구 행동·이전 화면 이동을 넣는다(FR-X4).

### 7.7 Unity 이관 방안 (T-8, 추후)

발표 버전은 HTML/JS UI다. Unity는 아래 원칙을 지키면 API·엔진 수정 없이 클라이언트만 새로 만들 수 있다.

| 공유 자산 | 내용 | Unity에서의 사용 |
|---|---|---|
| API 계약 | FastAPI OpenAPI(`/openapi.json`)와 공통 오류 형식 | C# 데이터 모델·클라이언트 생성, 상태 매핑 그대로 사용 |

- 금지: 화면 전용 계산(집계·검증·지표)을 JavaScript에 두지 않는다. 클라이언트는 표시·입력 검증만 한다.
