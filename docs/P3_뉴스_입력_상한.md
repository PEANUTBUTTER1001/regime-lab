## 문제와 이번 동작

여러 종목 검색에서 같은 기사가 반복되고, 출처별 목록을 단순 병합하면 후속 처리량이 급증한다. 이번 변경은 **네트워크 호출 전 요청 계획**, **응답 파싱**, **관측 버전 생성**, **마감 시각 기준 중복 제거·건수 제한**을 순수 함수로 구현한다. 수집기 전체 완성이나 기존 n8n 운영 반영을 뜻하지 않는다.

합성 입력 4,532개의 서로 다른 기사와 50개의 출처 간 중복을 넣고 선택 상한 40을 적용하면, 선택 40·중복 50·보류 4,492를 반환한다. 보류는 데이터 없음이나 수집 완료로 바꾸지 않는다. 이는 건수 제한이며 토큰 한도 보장은 아니다. 이후 요약 단계는 입력 길이·토큰 한도를 별도로 검사해야 한다.

## 함수 계약

- `request_plan`: 명시된 질의 목록의 공백·중복을 정리하고 한 질의의 여러 페이지보다 다른 질의 첫 페이지를 우선한다. 실행당 상한과 남은 일 한도 중 작은 값을 사용한다. `next_cursor`로 다음 순번을 넘겨 낮은 상한에서도 뒤쪽 질의가 굶지 않게 한다. `remaining_daily`는 호출자가 잠금 아래 실제 잔여량을 계산해 주어야 한다. 계획만으로 동시 실행·재시도 한도가 강제되지는 않는다.
- `parse_naver`: 오류 응답·잘못된 페이지·모순되는 건수를 정상 빈 결과로 처리하지 않는다. 잘못된 항목은 원문을 오류에 노출하지 않고 개수와 `partial`로 남긴다. `more_results`가 있어도 과거 기간의 완전 수집을 주장하지 않는다.
- `parse_feed`: UTF-8 RSS 2.0·Atom을 받으며 바이트·항목 상한을 필수로 요구한다. DTD/entity를 거부하고 다른 사이트를 조회하지 않는다. 초과 항목 수와 `partial`을 반환한다. HTTP 수신 단계에서도 바이트 제한이 필요하다.
- `observe`: 제목은 텍스트로 바꾸고 원문 URL을 식별자로 삼는다. `utm_*`, `gclid`, `fbclid`, fragment만 제거하며 기사 번호·알 수 없는 질의 값·HTTP/HTTPS 차이를 보존한다. 출처별 `doc_id`와 출처 공통 `article_key`를 분리한다. 같은 제목만으로 다른 URL을 합치지 않는다.
- `normalize_poll`: 같은 조회 묶음에서 같은 URL·동일 내용은 한 번만 처리한다. 같은 URL의 서로 다른 내용은 순서를 단정하지 않고 충돌로 격리한다. 기존 이력은 변경하지 않고 새 버전만 반환한다. 오류/충돌이 있으면 완료 커서를 넘기지 않는 것은 저장 유스케이스의 책임이다.
- `select_cutoff`: `first_seen_at`과 `available_at` 모두 마감 시각 이하인 최신 버전만 선택하고 URL 중복을 제거한 뒤 상한을 적용한다. 미래 버전을 넣어도 과거 결과가 변하지 않는다. 과거 소급 모드는 지원하지 않는다.

## 출처·시각·권한

기본 출처는 비활성이며 `SourcePolicy.check()`가 비활성 출처를 거부한다. `metadata_only`이면 요약과 원문 참조는 비운다. `summary_link`는 별도 권한 확인 이후 호출자가 설정해야 한다. 어느 값도 LLM 전송 허가가 아니다. 종목 질의나 제목 일치만으로 종목 연결을 확정하지 않는다.

네이버의 `pubDate`는 `naver_provided`, 피드 게시 시각은 `feed_pubdate`로 구분한다. 출처 시각은 분석 가능 시각을 앞당기지 않는다. 첫 관측과 변경 버전은 수집기가 관측한 시각 이후에만 사용할 수 있다. 시간대 없는 값·거꾸로 간 관측 시계는 거부한다.

네이버 요청 형식과 페이지 범위는 [공식 뉴스 검색 문서](https://developers.naver.com/docs/serviceapi/search/news/news.md)를 2026-10-07 확인했다. 해당 문서는 검색 API 동작 근거이며 기사 재사용·재전송 허가의 근거가 아니다.
