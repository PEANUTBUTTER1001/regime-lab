## 1. 디자인 철학

본 서비스는 시장을 빠르게 판단하도록 재촉하는 거래 화면이 아니라, 사용자가 **과거 데이터를 차분하게 비교·검증**하도록 돕는 분석 도구다.

- **차분한 신뢰감:** 어두운 바탕, 절제된 민트 강조, 안정적인 간격으로 복잡한 수치를 정리한다.
- **근거 우선:** 핵심 수치에는 표본 수·기간·데이터 상태를 함께 보인다. 예쁜 그래프가 근거를 대신하지 않는다.
- **평면적 명료성:** 표, 입력, 전략 설정은 깊이 효과보다 위계와 정렬로 구분한다.
- **비권유 표현:** “Buy”, “Strong signal”, “Top pick” 같은 행동 유도 표현을 사용하지 않는다. `Analysis target`, `Historical condition`, `Sample insufficient`처럼 분석 상태를 정확히 말한다.
- **예측과 과거의 분리:** 유사 패턴의 이후 움직임은 과거 사례임을 선·색·범례·문구로 분명히 구분한다.

브랜드 문구는 다음을 기본으로 한다.

```text
Find the pattern. See what's next.
Compare the past. Explore what comes next.
```

“See what’s next”는 확정적 미래 예측을 뜻하지 않으며, 화면에는 항상 과거 데이터 분석 고지를 함께 둔다.

## 2. 색상 시스템

### 2.1 기본 토큰

| 토큰 | 값 | 용도 |
|---|---|---|
| `bg-canvas` | `#0C1114` | 앱 전체 배경 |
| `bg-surface` | `#12191D` | 헤더, 사이드바, 카드 |
| `bg-control` | `#1B2429` | 입력칸, 일반 버튼, 비선택 메뉴 |
| `text-primary` | `#E8F0ED` | 제목, 본문, 입력값 |
| `text-secondary` | `#97A9A3` | 설명, 단위, Placeholder, 메타데이터 |
| `accent-mint` | `#88E6BC` | 주요 실행, 선택 상태, 핵심 강조 |
| `text-on-mint` | `#0C2B20` | 민트 배경 위 텍스트 |
| `accent-amber` | `#EAC07A` | 유사 패턴·과거 비교의 보조 강조 |

### 2.2 사용 규칙

- 민트는 한 화면에서 가장 중요한 행동 **하나**와 현재 선택 상태에만 사용한다. 주요 CTA가 둘 이상이면 사용자의 다음 행동을 먼저 재정의한다.
- 표·그래프의 긍정/부정 값에 민트만 사용하지 않는다. 수치 부호, `Gain`/`Loss` 레이블, 아이콘 또는 패턴을 함께 제공한다.
- `bg-surface`와 `bg-control`의 차이로 영역을 나누되, 모든 카드에 강한 테두리·그림자·그라데이션을 반복하지 않는다.
- 경고, 오류, 표본 부족 색상은 구현 시 접근성 대비를 만족하는 별도 의미 토큰으로 정의한다. 색상만으로 상태를 전달하면 안 된다.
- 차트의 장식용 색과 데이터 의미 색을 섞지 않는다. 로그인 배경 차트는 실제 분석 차트가 아닌 정적 장식이다.

## 3. 타이포그래피와 언어

### 3.1 폰트

- 기본 영문: 가독성이 검증된 산세리프체를 사용한다.
- 한글 전환 시: 한글 글리프가 포함된 TMP 폰트 에셋을 사용하며, 영문만 포함된 폰트로 대체하지 않는다.
- 숫자는 표·축·성과 카드에서 자릿수 폭이 안정적인 숫자 스타일을 사용한다.

### 3.2 크기와 위계

| 역할 | 기본 크기 | 용도 |
|---|---:|---|
| 페이지 제목 | 40 | `Strategy Builder`, `Results` |
| 카드 제목 | 28 | `Buy conditions`, `Sell & exit rules` |
| 사이드바 메뉴 | 26 | 주요 패널 탐색 |
| 실행 버튼 | 28 | `Run backtest` |
| 라벨·입력값 | 22 | 폼 입력, 표의 핵심 텍스트 |
| 진행 상태 | 32 | 실행 중 핵심 상태 |
| 보조 설명 | 16–18 | 단위, 메타데이터, 오류 설명 |

### 3.3 문구 원칙

- ~~기본 UI 언어는 영어로 통일한다.~~ → **2026-09-22 사용자 결정(E9): 기본 UI 언어는 한국어, 설정 화면(사이드바 최하단 ⚙)에서 영어로 바꿀 수 있다.** 선택한 언어 안에서는 부분 번역을 섞지 않는다.
- AI 보고서 본문과 데이터 한계 문구는 언어 설정과 무관하게 한국어로 생성한다(FR-L1). 비권유 고지는 한국어 화면에서 영어 원문을 함께 표기한다.
- 날짜는 `YYYY-MM-DD`, 금액은 `KRW`, 퍼센트는 `%`, 보유 기간은 `trading days`로 일관되게 쓴다.
- `No results yet`, `Sample insufficient`, `Data validation failed`, `Back to strategy`처럼 상태와 다음 행동을 함께 쓴다.
- 전략 성과에는 `Historical analysis — not investment advice.`를 고정 표기한다.

## 4. 레이아웃 기준

### 4.1 Canvas

| 항목 | 기준 |
|---|---|
| Render Mode | Screen Space - Overlay |
| Canvas Scaler | Scale With Screen Size |
| Reference Resolution | 1920 × 1080 |
| Screen Match Mode | Match Width Or Height |
| Match | 0.5 |
| 기본 Scale | 1, 1, 1 |

데스크톱 가로 화면이 우선이다. 1280px 이하 화면을 정상 데스크톱 화면으로 간주하지 않으며, 반응형 설계가 확정되기 전에는 카드 세로 배치 또는 Scroll View 중 하나를 명시적으로 적용한다. 콘텐츠가 잘린 상태를 허용하지 않는다.

### 4.2 공통 프레임

| 영역 | 기준 |
|---|---|
| Header | 상단 Stretch, 높이 120 |
| Sidebar | 좌측 Stretch, 너비 360, Header 아래부터 하단까지 |
| Content Area | 좌측 360, 상단 120을 제외한 전체 영역 |
| 콘텐츠 패널 | Content Area 안에서 전체 Stretch |
| 사이드바 버튼 | 너비 312, 높이 72, 좌측 24 |
| 콘텐츠 기본 여백 | 좌우 48, 상단 32 |

공통 헤더와 사이드바는 MainScene에서 유지한다. `Progress`는 실행 중 상태이지 별도 사이드바 메뉴가 아니다. 선택된 메뉴는 민트 배경·어두운 글자, 비선택 메뉴는 `bg-control`·밝은 글자를 사용한다.

### 4.3 간격과 정렬

- 기본 간격 단위는 8이다. 카드 안쪽 여백은 24, 카드 간 간격은 36 이상을 기본으로 한다.
- 라벨과 입력칸은 같은 세로축에 맞추고, 한 카드 안에서는 입력 높이와 레이블 간격을 통일한다.
- 화면의 가장 중요한 행동은 우측 하단 또는 사용 흐름의 끝에 둔다. Strategy Builder의 `Run backtest`는 우측 하단에 고정한다.
- 숫자 열은 오른쪽 정렬, 텍스트 열은 왼쪽 정렬한다. 퍼센트·금액·기간 단위는 값과 분리하지 않는다.

## 5. 컴포넌트 지침

### 5.1 카드와 패널

- 카드 배경은 `bg-surface`, 입력·세부 제어 영역은 `bg-control`을 사용한다.
- 카드 제목 → 짧은 설명 → 입력/결과 순서로 배치한다.
- 장식 테두리보다 제목·간격·표면 명도 차이로 그룹을 인식시킨다.
- 결과가 없는 카드에는 빈 표를 남기지 말고, 원인과 다음 행동을 포함한 Empty State를 사용한다.

### 5.2 버튼

| 유형 | 스타일 | 예시 |
|---|---|---|
| Primary | `accent-mint` 배경 + `text-on-mint` | Run backtest, View results |
| Secondary | `bg-control` 배경 + `text-primary` | Back to strategy, Cancel |
| Text/Link | 투명 배경 + 민트 또는 밝은 텍스트 | Create an account, Edit conditions |
| Disabled | 낮은 대비의 제어 배경 + 설명 | 데이터 또는 필수 입력이 없을 때 |

- 버튼은 기본·hover·pressed·focus·disabled 상태를 모두 제공한다.
- 클릭 가능 영역은 최소 44×44 UI 단위를 확보한다.
- `Cancel`은 파괴적 작업으로 보이게 과장하지 말고, 취소 후 결과가 남지 않는지 안내한다.

### 5.3 입력, 드롭다운, 토글

- Label은 입력칸 위에 항상 표시한다. Placeholder는 Label을 대체하지 않는다.
- 초기값은 부모 입력 컴포넌트의 값으로 설정한다. Placeholder는 빈 값일 때의 입력 예시만 제공한다.
- 숫자 입력에는 단위·허용 범위·형식을 즉시 보여준다. 예: `Stop loss (%)`, `Holding days`.
- 오류는 입력 바로 아래에 문장으로 표시하고, 색상 외에 아이콘 또는 텍스트를 함께 사용한다.
- Toggle은 체크 상태뿐 아니라 라벨 전체를 클릭할 수 있게 하며, 키보드 포커스를 지원한다.

### 5.4 테이블과 성과 카드

- 성과 카드에는 값만 두지 말고 기간·거래 수·계산 기준을 함께 표시한다.
- 거래 300건 미만은 `Sample insufficient` 상태로 명확히 표시하며, 일반 성과 수치와 같은 강조 수준을 주지 않는다.
- 차트의 수치와 표의 수치는 같은 `run_id` 결과를 사용한다.
- Profit factor, win rate, excess return 등은 툴팁이나 보조 설명으로 계산 기준을 제공한다.

## 6. 화면별 가이드

### 6.1 LoginScene

- 좌측 소개 영역은 약 53%, 우측 폼 영역은 약 47%로 둔다.
- 좌측의 겹친 차트는 브랜드 분위기를 위한 정적 장식이다. 클릭·포커스·스크린리더 대상에서 제외한다.
- 우측 폼은 한 번에 로그인 또는 가입 중 하나만 보인다. 초기 상태는 로그인 폼이다.
- 비밀번호 입력은 항상 마스킹하며, 실제 인증·계정 보관 여부를 UI 완료 상태와 혼동하지 않는다.

### 6.2 Strategy Builder

세 개의 카드가 같은 높이로 나란히 배치되는 것이 핵심이다.

| 카드 | 역할 | 우선 정보 |
|---|---|---|
| Buy conditions | 패턴 선택과 AND/OR | 선택 조건 수와 조합 방식 |
| Sell & exit rules | 청산 조건 | 손절·익절·보유일·미사용 상태 |
| Universe & period | 대상·기간 | 시장, 기간, 유동성, 시총 그룹 |

- 카드 위치 기준은 X 48 / 548 / 1048, Y -160, 너비 464, 높이 680이다.
- 전략 이름은 우측 상단, 실행 안내와 실행 버튼은 하단에 고정한다.
- `Execution: Next-day open`, `Round-trip trading cost: 0.30%`를 실행 전 항상 표시한다.
- Run 버튼을 활성화하기 전 필수 조건·예상 대상 종목 수·입력 오류를 확인한다.

### 6.3 ProgressPanel

- 진행 정보의 우선순위는 `현재 단계 → 처리 수/전체 수 → 경과 시간 → 예상 남은 시간`이다.
- 서버가 실제로 제공하지 않은 진행률이나 남은 시간을 애니메이션으로 만들어 내지 않는다.
- 실패·취소 상태에는 이유와 `Back to strategy` 또는 재시도 행동을 표시한다.

### 6.4 Results 및 Stock Detail

- Results는 전체 전략의 질문에 답하고, Stock Detail은 특정 종목의 근거를 설명한다. 두 화면의 역할을 섞지 않는다.
- 국면 표·시장×시총 히트맵·손익 분포·기간 분할 비교는 같은 분석 실행 결과에서 파생한다.
- 차트에는 관측 기간, 전략 진입·청산 마커, 이동평균선, 국면 배경의 범례를 제공한다.
- 손익이 좋은 종목을 순위처럼 과도하게 강조하지 않으며, 표본 수와 한계를 동등하게 표시한다.

### 6.5 AI Report 및 Morning Briefing

- 보고서는 요약을 먼저, 근거 수치와 데이터 상태를 다음에 둔다.
- AI 문장은 새 수치를 만들거나 권유 표현을 사용하지 않는다.
- Morning Briefing은 `야간 상태 → 충격 근거 → 테마 분석 → 조건부 과거 성과 → 한계/고지` 순서로 읽힌다.
- 뉴스·야간 데이터가 없으면 빈 브리핑을 숨기지 말고 `Data validation failed` 또는 `Data unavailable`과 사유를 표시한다.

### 6.6 유사 패턴 비교

- 기본은 2D 정규화 선 차트다. 시작값 100 또는 수익률 축처럼 비교 가능한 단위를 축·범례에 명시한다.
- 3D는 여러 과거 사례의 깊이 방향 비교가 실제로 유용할 때만 사용한다. 표·입력·성과 요약에 3D를 사용하지 않는다.
- 현재 관측 구간, 유사 과거 구간, 과거 후속 결과는 서로 다른 선 종류와 범례로 구분한다.
- 과거 후속 결과는 `Historical follow-through`로 명시하며 `Forecast` 또는 확정적 미래 표현을 쓰지 않는다.

## 7. 차트와 데이터 시각화

### 7.1 차트 공통 원칙

- 축, 단위, 기간, 범례, 데이터 기준일을 차트 가까이에 둔다.
- 툴팁은 날짜·값·단위·시리즈 이름을 제공한다.
- 장식용 그래프와 실제 분석 데이터 그래프를 같은 시각 언어로 표현하지 않는다.
- 예측·시뮬레이션·과거 실제 데이터가 함께 있을 때는 색 외에 선 종류, 영역 라벨, 경계선으로 구분한다.
- 색약 사용자가 구분할 수 있도록 선 두께·점선·마커를 병행한다.

### 7.2 민트와 앰버의 데이터 사용

- 민트는 현재 선택된 전략·활성 시리즈·확정된 사용자 선택을 나타낸다.
- 앰버는 유사 과거 사례 또는 보조 비교 시리즈를 나타낸다.
- 매수·매도·이익·손실처럼 의미가 다른 데이터는 차트 범례와 텍스트를 함께 제공하며, 민트/앰버의 의미와 충돌하지 않게 별도 토큰을 정한다.

## 8. 접근성·상태·품질 기준

### 8.1 접근성

- 키보드로 로그인 폼, 사이드바, 모든 입력, 토글, 드롭다운, 버튼을 순서대로 탐색하고 실행할 수 있어야 한다.
- focus 상태는 배경 변화만이 아니라 명확한 외곽선 또는 충분한 대비로 보인다.
- Raycast Target은 장식 배경·장식 텍스트·정적 차트에 끄고, 실제 입력·버튼에는 켠다.
- 색상만으로 성공·실패·선택·표본 부족을 전달하지 않는다.
- 핵심 텍스트·입력값·버튼 텍스트는 어두운 배경에서 읽을 수 있는 대비를 유지한다.

### 8.2 상태 디자인

| 상태 | 표시 내용 | 권장 행동 |
|---|---|---|
| Loading | 현재 단계, 실제 진행 정보 | 기다리기 또는 취소 |
| Empty | 아직 실행 결과가 없음 | Build a strategy |
| Sample insufficient | 거래 수와 분석 제한 | 조건 수정 또는 전체 결과 보기 |
| Validation failed | 문제 필드·데이터·사유 | 수정 또는 재시도 |
| Network/server error | 사람이 이해할 수 있는 오류 문구 | Retry 또는 이전 화면 |
| Cancelled | 취소 시점과 결과 미생성 여부 | Back to strategy |

### 8.3 시각 QA 체크리스트

- [ ] 주요 CTA는 화면당 하나이며 민트가 과도하게 반복되지 않는다.
- [ ] 모든 수치에 단위·기간·거래 수 또는 데이터 상태가 있다.
- [ ] 빈 결과·오류·표본 부족 상태가 일반 결과와 구분된다.
- [ ] 과거 유사 사례가 예측처럼 읽히지 않는다.
- [ ] 1920×1080 기준에서 세 카드·표·하단 실행 영역이 겹치거나 잘리지 않는다.
- [ ] 키보드 포커스와 클릭 대상이 장식 요소에 가로막히지 않는다.
- [ ] 모든 화면에서 비권유 고지가 확인된다.

## 9. 구현 인계 메모

- Unity UI는 Python 결과 파일을 직접 읽지 않고 API의 JSON 응답만 사용한다.
- 긴 분석은 `run_id` 기반의 실행 요청·상태 조회·결과 조회 흐름으로 표시한다.
- 3D 차트는 `RenderTexture → RawImage` 구성을 사용할 수 있으나, Canvas Overlay에서 배경이 카메라 화면을 가리지 않는지 실제 구현으로 검증한다.
- 동일 카드·버튼·입력 컴포넌트는 시각이 안정된 뒤 Prefab으로 정리한다.
- 이 문서는 디자인 기준이다. API 경로, 인증 방식, 데이터 계산은 `SRS.md`와 별도 기술 설계에서 확정한다.
