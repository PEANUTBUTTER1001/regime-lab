## 1. 디자인 철학

이 서비스는 시장을 빠르게 판단하도록 재촉하는 거래 화면이 아니다. 사용자가 **과거 데이터를 차분하게 비교·검증**하도록 돕는 분석 도구다.

- **작업 중심:** 사용자의 핵심 작업은 "조건을 정한다 → 실행한다 → 판정을 읽는다 → 근거(종목·거래·공시)를 확인한다"이다. 이 네 단계를 한 화면(작업면)에 두고, 확인하려고 화면을 옮겨 다니지 않게 한다.
- **각지고 단단한 톤:** 모서리 2px, 1px 구분선, 숫자 고정폭. 카드·그림자·그라데이션을 반복하지 않고 구분선과 표면 명도로 묶음을 나눈다.
- **근거 우선:** 핵심 수치에는 표본 수·기간·데이터 상태를 함께 보인다. 그래프가 근거를 대신하지 않는다.
- **비권유 표현:** "매수 추천", "Strong signal", "Top pick", "최적"처럼 행동을 부추기거나 결론을 단정하는 말을 쓰지 않는다. "분석 대상", "표본 부족", "참고"처럼 분석 상태를 정확히 말한다.
- **예측과 과거의 분리:** 예측은 회색 구간과 방향으로만 보이고 고정 문구를 붙인다(E17, §8.8).

### 2.3 사용 규칙

- **민트는 실행 버튼 하나.** `--mint` 바탕은 화면에서 가장 중요한 행동(백테스트 실행, 탐색 실행) 하나에만 쓴다. 선택·포커스·통과 표시는 `--accent`를 쓴다. 다크에서는 둘이 같은 색이지만 이름을 섞지 않는다. 라이트에서 민트를 글자·선에 쓰면 대비가 1.5 안팎이라 읽히지 않기 때문이다.
- **손익은 한국식.** 0보다 크면 `--up`과 ▲, 0보다 작으면 `--down`과 ▼, 0은 색 없음. +/− 부호는 글자로 함께 둔다. 손익이 아닌 수치(채점 차이, 백분위, 거래 수)에는 이 색을 쓰지 않는다.
- **빨강은 손익·매수에만.** 오류·미통과·입력 오류는 `--error`(주황)와 ✕ 기호를 쓴다.
- **표본 부족은 앰버 빗금.** 300건(`analysis.min_cell_trades`) 미만 칸은 `--hatch` 빗금을 깔고 값을 흐리게(불투명도 .5) 둔다. 표본 수 글자는 `--amber`로 쓴다. 기준 숫자는 설정에서 읽고 고정 문장으로 쓰지 않는다.
- **색만으로 상태를 전하지 않는다.** 통과 ✓, 미통과 ✕, 상승 ▲, 하락 ▼, 매수 ▲, 매도 ■, 표본 부족 "부족" 글자를 함께 쓴다.
- **차트 색도 토큰에서.** 차트 라이브러리에 색을 직접 적지 않고 CSS 변수 값을 읽어 넘긴다(§9).

## 3. 타이포그래피

### 3.1 서체

| 역할 | 서체 순서 | 쓰는 곳 |
|---|---|---|
| 본문 (`--sans`) | `"Pretendard", "Malgun Gothic", "Apple SD Gothic Neo", "Segoe UI", system-ui, sans-serif` | 모든 한글·영문 글자 |
| 숫자 (`--mono`) | `"JetBrains Mono", "SF Mono", Consolas, ui-monospace, monospace` + `font-variant-numeric: tabular-nums` | **숫자·날짜·코드·실행 ID에만** |

- 고정폭 서체를 한글이 섞인 칸(종목명, 설명)에 쓰지 않는다. 한글이 없는 서체라 대체 서체로 바뀌며 자간이 흐트러진다.
- 외부 폰트 파일은 내려받지 않는다(설치된 서체 순서대로 쓴다).

### 3.2 크기 5단계

| 토큰 | 크기 / 굵기 / 행간 | 용도 |
|---|---|---|
| `--fs-meta` | 11px / 400–700 / 1.5 | 라벨, 메타, 힌트, 표 머리, 범례, 대문자 라벨(영문만, 자간 .1em) |
| `--fs-body` | 12px / 400–600 / 1.5 | 본문, 표 칸, 탭, 메뉴, 버튼 |
| `--fs-input` | 13px / 400–700 / 1.5 | 입력값, 검증 질문, 실행 버튼, 섹션 제목(구획) |
| `--fs-head` | 16px / 700 / 1.4 | 판정 제목, 상태 화면 제목, 종목 이름 |
| `--fs-kpi` | 24px / 700 / 1.25 (`--mono`) | 핵심 지표 4개 |

- 이 다섯 크기 밖의 값을 쓰지 않는다. 11px 아래는 없다.
- 위계는 크기·굵기·위치로 만든다. 같은 크기에서 굵기만 바꿔 위계를 만들 수 있다.
- 한글에는 대문자 변환·넓은 자간을 쓰지 않는다.

## 5. 레이아웃

### 5.1 앱 틀

```text
┌ 상단바 40 ─────────────────────────────────────────────────────────┐
│ 브랜드(메뉴 폭) │ 조건 열 제목 │ 실행 맥락(가운데 열 위) │ 상태·테마·설정 │
├─ 메뉴 208 ─┬─ 조건 열 ─┬────── 가운데 열 ──────┬─ 오른쪽 열 ─┤
│ 4묶음 고정 │ 전략 조건 │ 실행 결과 (또는 근거) │ 근거 (또는 결과) │
│            │  [실행]   │                        │             │
├────────────┴───────────┴────────────────────────┴─────────────┤
│ 비권유 고지 (항상)                                             │
└────────────────────────────────────────────────────────────────┘
```

- 앱은 화면 높이에 맞춘다(`100dvh`). 페이지 전체가 아니라 **열마다** 세로로 스크롤한다.
- 가로 스크롤은 페이지에 생기지 않는다. 넓은 표만 그 표 안에서 가로로 움직인다.

### 5.2 상단바 = 열의 머리

- 상단바는 메뉴를 두지 않는 **맥락 줄**이다. 칸마다 아래 열과 **같은 폭 변수**(`--rail-w`, `--col1`, `--col3`)를 써서 칸 경계선이 열 경계선과 정확히 겹친다. 열 폭을 끌어서 바꾸면 상단바 칸도 같이 움직인다.
- 칸 내용

| 칸 | 내용 |
|---|---|
| 메뉴 위 | 브랜드 표시(2px 정사각 고리 + `REGIME-LAB`). 좁은 화면에서는 메뉴 열기 ☰ |
| 조건 열 위 | 화면 이름(`전략 만들기` 또는 `실행 결과`)과 묶음 이름 |
| 가운데 열 위 | 실행 맥락: 상태 점 · 전략 이름 · 기간 · 거래 수 · 검증 n/3. 작업면이 아닌 화면은 화면 이름과 한 줄 설명 |
| 오른쪽 열 위 | 테마 전환 ☀/☾ · 데이터 기준일 · 종목 범위(표본 30종목이면 주의 표시) · 게스트 표시 · 설정 ⚙ |

- **줄어드는 순서:** 칸 폭이 줄면 기간 → 거래 수 → 검증 표시 순으로 숨기고, 전략 이름은 줄임표(…)로 줄인다. 전체 이름은 `title`로 남긴다. 넘치는 부분을 잘라서 숨기지 않는다(`overflow:hidden`으로 컨트롤이 사라지면 결함).
- 상단바 안 컨트롤 높이는 24px 하나다. 배지 안에 배지를 넣지 않는다.

### 5.3 왼쪽 메뉴 (고정)

- E18의 4묶음을 그대로 쓴다: **전략 시험하기**(전략 만들기 · 목표로 전략 찾기 · 저장한 전략 · 백테스트 기록), **결과 보기**(실행 결과), **공시·뉴스**(공시·뉴스 검색 · 공시·뉴스 목록 · 영향 분석), **시장 참고**(봉 예측 · 시장 브리핑).
- 1024px 이상에서는 **항상 208px로 펼쳐 둔다.** 접기 버튼·아이콘만 남기는 상태가 없다.
- 1024px 미만에서는 상단바 ☰로 여는 서랍(폭 240px)이 된다. 메뉴를 고르면 닫히고, Esc·바깥 누르기로도 닫힌다.
- 아이콘은 이모지가 아닌 기하 기호 한 벌(`⌘ ⟲ ☆ ☰ ▦ ⌕ ▤ ◇ ◫ ◌`)을 16px 칸 안에 가운데 정렬한다. 현재 화면은 `--sel` 바탕과 왼쪽 2px `--accent` 선, `aria-current="page"`.
- 내용이 없는 메뉴는 `준비 중` 태그를 붙인다.
- 메뉴 맨 아래에는 계정(게스트 표시 또는 이메일)과 로그인/로그아웃을 둔다. 설정은 상단바 오른쪽 ⚙ 하나로 연다(같은 목적지를 두 곳에 두지 않음).

### 5.4 작업면 3열 (전략 만들기 · 실행 결과)

| 열 | 내용 | 폭 |
|---|---|---|
| 조건 열 | 전략 조건 입력 + 아래 고정 실행 영역 | 기본 `clamp(264, 22vw, 320)`, 최소 240(1024–1279px 220), 최대 520 |
| 가운데 열 | 실행 결과 (진행 중이면 진행 상황) | 남는 폭, **최소 400**(1024–1279px 300) |
| 오른쪽 열 | 근거: 종목별 거래 · 공시·뉴스 · AI 보고서 | 기본 `clamp(300, 26vw, 400)`, 최소 280(1024–1279px 260), 최대 720 |

- 열 폭을 맞출 때는 가운데 최소 폭을 먼저 지킨다. 저장한 폭이 지금 창에 안 맞으면 오른쪽 열 → 조건 열 순서로 최소값까지 줄인다.
- **조건 열은 1024px 이상에서 늘 보인다(10-13 결정 E21).** 상단 버튼으로 여는 서랍을 두지 않는다. 전략 만들기와 실행 결과(결과 보기 › 실행 결과)는 같은 3열이며, 실행 결과는 그 실행의 주소(`#/runs/<id>/…`)로 연다는 점만 다르다. 결과를 넓게 보려면 조절바로 조건 열을 줄이거나 ⇄를 쓴다.

### 5.5 화면 종류

| 종류 | 화면 | 열 |
|---|---|---|
| 작업면 | 전략 만들기, 실행 결과 | 조건 · 결과 · 근거 |
| 2열 | 목표로 전략 찾기·영향 분석 (조건 = 조건 열과 같은 `--col1`, 조절바 있음 / 결과), 공시·뉴스 검색·목록 (목록 / 상세 = 오른쪽 열과 같은 `--col3`, 조절바 있음), 봉 예측 (종목·봉 단위 240 / 차트, P2-10) | |
| 1열 | 저장한 전략, 백테스트 기록, 시장 브리핑, 설정 | 본문 최대 폭 880(목록형), 표는 전체 폭 |

하나의 실행에 딸리지 않은 화면(공시·뉴스, 시장 참고)에는 3열을 씌우지 않는다.

### 5.6 반응형 단계

| 폭 | 메뉴 | 작업면 | 상단바 |
|---|---|---|---|
| 1280 이상 | 고정 208 | 3열 | 칸 4개 (메뉴·조건·맥락·상태) |
| 1024–1279 | 고정 208 | 3열 그대로, 최소 폭만 줄임(조건 220 · 가운데 300 · 근거 260) | 칸 4개 |
| 1024 미만 | 서랍 | 한 열 + 위쪽 전환 버튼 `조건 / 결과 / 근거` (2열 화면은 두 칸) | 칸 3개 (☰·브랜드 / 맥락 / 상태) |

- 좁은 화면에서는 읽는 순서대로 재배치한다. 실행을 시작하면 `결과`로, 국면 칸·종목을 누르면 `근거`로 넘어간다.
- 1024 미만에서는 자리 바꾸기와 경계선 조절바를 숨긴다(한 열이라 뜻이 없음).

## 6. 상호작용

### 6.1 가운데 ↔ 오른쪽 자리 바꾸기

- 오른쪽 열 머리 끝의 `⇄` 아이콘 버튼(24px). 누르면 오른쪽 열 내용이 가운데로, 가운데 내용이 오른쪽으로 간다. 버튼은 바꾼 뒤에도 **오른쪽 열에** 남아, 다시 누르면 되돌아온다.
- `aria-pressed`로 상태를 알리고, 라벨은 "<오른쪽 열 이름> 열을 가운데로 옮기기"다. 바꾼 뒤 초점은 같은 버튼에 남는다.
- 폭 변수는 **자리**에 붙어 있다. 바꿔도 가운데는 넓고 오른쪽은 좁다.
- 작업면 두 화면(전략 만들기·실행 결과)에 같은 상태를 쓴다.

### 6.2 경계선 조절바

- 조건|가운데, 가운데|오른쪽 경계에 조절바를 둔다(누르는 폭 9px, 가운데 1px 선, 세로 32px 손잡이 3px). 마우스를 올리거나 초점을 받으면 `--accent`로 바뀐다.
- `role="separator"`, `aria-orientation="vertical"`, `aria-valuenow/min/max`(px), `aria-valuetext`, 라벨("조건 열 너비", "오른쪽 근거 열 너비").

| 조작 | 결과 |
|---|---|
| 끌기 | 폭 변경. 끄는 동안 현재 px 표시. 가운데 최소 폭(400, 1024–1279px 300) 아래로는 멈춤 |
| 두 번 누르기 / Enter | 기본 폭으로 |
| ← / → | 16px씩 (오른쪽 열 조절바는 ←가 넓히기) |
| Shift + ← / → | 64px씩 |
| Home / End | 최소 / 최대 |

- 끄는 동안 페이지 글자가 선택되지 않게 하고 커서를 `col-resize`로 고정한다. 차트는 끄기가 끝나거나 열 크기가 바뀔 때 다시 맞춘다.
- 조건 열 조절바는 1024px 이상의 작업면(전략 만들기·실행 결과)과 왼쪽 입력 열이 있는 2열 화면에 있다.

### 6.3 테마 전환

- 상단 오른쪽 칸 맨 앞의 아이콘 버튼. 다크일 때 ☀(라이트로), 라이트일 때 ☾(다크로). 라벨은 "라이트 테마로 바꾸기" / "다크 테마로 바꾸기".
- 처음 열면 기기 설정(`prefers-color-scheme`)을 따른다. 버튼으로 고르면 그 값을 저장하고 다음에도 쓴다. 저장값이 없을 때는 기기 설정이 바뀌면 따라 바꾼다.
- 첫 그리기 전에 테마를 정해 깜빡임이 없게 한다(`<head>` 안 짧은 스크립트).
- 차트는 테마가 바뀌면 새 색으로 다시 그린다.

### 6.4 브라우저 저장

| 키 | 값 | 용도 |
|---|---|---|
| `rl.theme` | `"light"` / `"dark"` | 고른 테마 |
| `rl.layout` | `{c1, c3, swap}` (px 또는 null) | 열 폭, 자리 바꾸기 |
| `rl.prefs` | `{detailOpen, defsOpen, stockSort}` | 요약의 자세한 지표·지표 정의 펼침(기본 펼침), 종목별 거래 정렬(기본 `trades_desc`) |
| `rl.favs:<사용자 id 또는 guest>` | 종목 코드 배열 | 종목 즐겨찾기 (모든 실행에 공통) |
| `rl.recentStocks:<사용자 id 또는 guest>` | `[{code, name}]` 최대 8 | 최근 조회 종목 (종목 상세를 연 순서) |

- `localStorage` 읽기·쓰기는 모두 `try/catch`로 감싼다. 막힌 브라우저(사생활 보호 모드 등)에서도 화면은 기본값으로 동작하고, 고른 값은 그 페이지를 여는 동안만 메모리에 기억한다(`web/js/state.js`).
- 이 값들은 이 브라우저의 편의 설정일 뿐이다. 서버에 보내지 않는다.

### 6.5 실행 흐름

- `백테스트 실행`을 누르면 **가운데 열**에 진행 상황이 나온다(현재 단계, 처리 수/전체 수, 경과 시간, 취소). 서버가 주지 않은 진행률·남은 시간을 만들어 내지 않는다.
- 끝나면 같은 자리에서 결과로 바뀌고, 상단바 실행 맥락이 새 실행으로 바뀐다. 실패·취소는 이유와 다음 행동(다시 실행, 백테스트 기록)을 보인다.
- `Ctrl+Enter`(macOS `⌘+Enter`)로 실행한다. 입력 오류가 있으면 실행하지 않고 오류 칸으로 초점을 옮긴다.

### 6.6 키보드·모션

- 탭 줄은 `role="tablist"`이며 ←/→/Home/End로 옮긴다. 선택 탭만 `tabindex=0`.
- Esc는 열린 메뉴 서랍(1024px 미만)과 ? 도움말을 닫는다.
- **기록 이동:** 종목 상세를 열면 브라우저 기록을 하나 남긴다(`#/runs/<id>/stock/<종목>`, 전략 만들기는 `#/builder?stock=<종목>`). 뒤로가기(마우스 뒤로 버튼·Alt+←)는 오른쪽 열만 종목 목록으로 되돌리고 가운데 탭·스크롤·조건 입력은 그대로 둔다. 같은 작업면 안의 기록 이동은 화면이 직접 처리한다(`workspace.js` `setRouteGuard`).
- 모션은 서랍 열고 닫기(0.16초)와 실행 중 상태 점 깜빡임뿐이다. `prefers-reduced-motion`이면 모두 끈다. 화면 전환 애니메이션은 두지 않는다.

## 7. 컴포넌트

### 7.1 묶음 표현 — 카드 대신 구분선

- 한 작업에 속한 입력·결과는 카드로 쪼개지 않는다. 구획(`sec`, 안쪽 여백 12–14px)과 아래 1px 구분선으로 나눈다.
- 구획 머리: 번호(고정폭, `--dim`) + 제목(13px 700) + 오른쪽 보조 문구(11px `--dim`).
- 카드는 **독립된 대상에 행동이 붙을 때만** 쓴다(예: 저장한 전략 한 개 = 불러오기·삭제).

### 7.2 열 머리 (탭 줄)

- 높이 32px, `--surface` 바탕, 아래 1px 선. 탭은 12px 600, 선택 탭은 `--canvas` 바탕 + 아래 2px `--accent`.
- 탭이 넘치면 **탭 영역만** 가로로 스크롤한다. 오른쪽 보조 버튼(전략 저장, ⇄)은 고정 위치에 남는다. 탭 글자는 줄바꿈하지 않는다.

### 7.3 버튼

| 종류 | 모양 | 예 |
|---|---|---|
| 실행 | `--mint` 바탕 + `--mint-ink` 13px 800, 높이 36, 폭 100% | 백테스트 실행, 탐색 실행 |
| 일반 | `--control` 바탕 + `--line-strong` 테두리, 높이 30 | 다시 실행, 불러오기 |
| 조용한 | 투명 바탕 + 테두리 | 전략 저장, 취소 |
| 위험 | 조용한 버튼 + `--error` 글자 | 삭제(확인 단계에서만) |
| 아이콘 | 24×24, 테두리 | 테마, 설정, ⇄, ☰, 휴지통(색 없는 1.5px 선 SVG — 이모지를 쓰지 않음) |
| 즐겨찾기 별 | 24×24, 테두리 없음 | 꺼짐 ☆ `--muted`, 켜짐 ★ `--accent`(사용자가 고른 상태). 앰버(표본 부족)는 쓰지 않는다. `aria-pressed`, 누르면 행은 열리지 않는다 |
| 링크 | 밑줄 글자 | 저장한 전략, 전체 보기 |

- 상태: 기본 · 올림 · 누름 · 초점(2px `--accent` 외곽선) · 비활성(이유를 옆에 글로).
- 삭제는 같은 자리에서 "삭제할까요? [삭제] [취소]"로 한 번 더 묻는다.

### 7.4 입력

- 라벨은 입력칸 위에 항상 보인다. 자리표시 글자는 라벨을 대신하지 않는다.
- 숫자 입력은 오른쪽 정렬 + 단위 칸(`%`, `거래일`, `억 원 이상`)을 붙인다.
- 오류는 입력칸 바로 아래에 `✕ 문장`(`--error`)으로, 입력칸 테두리도 `--error`, `aria-invalid="true"`. 허용 범위는 설정(`exit_limits` 등)에서 읽는다.
- 켜고 끄는 청산 조건은 [체크박스 + 이름] | [입력칸] 한 줄. 꺼지면 입력칸 비활성. 기본 꺼진 조건 3개(트레일링·본전·이동평균 이탈)는 `추가 매도 조건` 접기 안에 두고, 하나라도 켜져 있으면 펼쳐서 연다.
- 여러 개를 고르는 값(시장·규모·탐색 축)은 토글 버튼(`aria-pressed`, 높이 28).

### 7.5 표

- 12px. 머리는 11px 600 `--muted`, `--surface` 바탕, 스크롤해도 위에 붙는다.
- 숫자 열은 오른쪽 정렬·고정폭, 글자 열은 왼쪽 정렬.
- 누를 수 있는 행은 `tabindex=0` + Enter로 열고, 선택 행은 `--sel` 바탕 + 왼쪽 2px `--accent`.

### 7.6 결과 화면 부품

| 부품 | 규칙 |
|---|---|
| 판정 | 16px 제목 + 한 줄 설명 + 메타(기간·대상·비용·실행 ID). 분석 대상이면 왼쪽 3px `--accent` 선과 ●, 아니면 `--line-strong` 선과 ✕ n/3 |
| 질문형 검증 3줄 | 질문(13px 600) / 근거 수치 한 줄(`--muted`) / 오른쪽 `✓ 통과` 또는 `✕ 미통과`. 상세 수치(p·q·m·백분위·분할일)를 숨기지 않는다 |

### 7.7 상태

| 상태 | 보여 줄 것 | 다음 행동 |
|---|---|---|
| 실행 없음 | "아직 실행한 전략이 없습니다" + 할 일 | 저장한 전략 열기, 백테스트 기록 |

### 7.8 알림

- 화면 오른쪽 아래, `--control` 바탕, 왼쪽 2px `--accent`, 3초 뒤 사라짐, `role="status"`. 되돌릴 수 없는 결과(삭제)는 알림만으로 확인받지 않는다.

### 7.9 ? 도움말 (토글팁) — v1 §5.5 유지

- 마우스 올리기·키보드 초점·클릭(탭)으로 열고, Esc·바깥 클릭·초점 이동으로 닫는다. 한 번에 하나만.
- 통계·청산 용어 옆에만 둔다. 메뉴·모든 입력칸에는 두지 않는다. 판정·표본 부족·고지는 도움말에 숨기지 않는다.
- 문구는 `i18n.js`의 `help.*` 한국어·영어, 1–2문장. 설정에 따라 바뀌는 숫자와 권유 표현은 넣지 않는다.

## 8. 화면별 가이드

### 8.1 전략 만들기 (작업면)

- 조건 열 구획: `1 매수 조건`(패턴 14종 목록, 패턴별 수치는 펼쳐서 조정, 결합 방식) → `2 매도 조건`(손절·익절·최대 보유, 추가 매도 조건 접기) → `3 대상·기간`(시장, 규모, 거래대금 하한, 시작·종료일) → 전략 이름.
- 조건 열 아래 고정 영역: 조건 요약(패턴 / 청산 / 대상 종목 수·왕복 비용 0.30%·다음 날 시가 체결) → 오류 수 → 실행 버튼. 대상 종목 수는 서버 미리보기 값만 쓴다.
- 가운데: 지난 실행 결과(없으면 실행 없음 상태). 오른쪽: 근거.

### 8.2 실행 결과 (작업면 넓게)

- 가운데 탭: **요약**(판정 → 검증 3줄 → 핵심 지표 → 국면 × 규모 → 청산 사유별 건수 → 자세한 지표) · **곡선·분포**(자산곡선, 손익 분포) · **국면·기간**(기간 분할 표와 판정, 국면 기준 설명).
- 한 실행에 전략이 여러 개면 가운데 열 머리 바로 아래에 전략 선택 줄을 둔다.
- 오른쪽 탭: **종목별 거래**(표 → 행을 누르면 같은 열에서 종목 상세: 가격 차트·매수 ▲·매도 ■·국면 음영, 거래 목록, ← 종목 목록) · **공시·뉴스**(거래 줄의 "근거"를 누르면 그 종목의 as_of = 진입일 08:59 KST 이전 자료, 최근 30일, `/api/evidence/documents`) · **AI 보고서**(숫자 대조 상태, 본문, 근거 수치, 데이터 상태).
- 종목별 거래 도구 줄: 종목 찾기(코드·이름) · ★ 즐겨찾기만 · 정렬 드롭다운(거래 수 많은/적은 순, 승률 높은/낮은 순, 평균 순수익률 높은/낮은 순, 종목 이름 가나다순; 같은 값이면 거래 수 → 코드). 표 캡션에 고른 기준과 "보기 순서이며 추천 순위가 아님"을 함께 쓴다. 기본은 거래 수 많은 순. 그 아래 최근 조회 칩(최대 8, 이 실행에 없는 종목은 비활성).
- 종목 상세 거래 표: 칸 줄바꿈 없이 표 영역(최대 `min(60vh, 520px)`) 안에서 가로·세로로 넘긴다. 머리와 첫 열(진입일) 고정.
- 요약의 자세한 지표와 지표 정의는 처음에 펼친 채 보이고, 접으면 그 상태를 기억한다.
- 국면 × 규모 칸을 눌러 종목을 좁히는 동작은 지금 결과 형식(종목 목록에 칸 분해 없음)으로 만들 수 없어 넣지 않는다(E19). 결과 형식을 바꾸는 후속 작업에서 다룬다.
- 주소: `#/runs/<id>/results`, `#/runs/<id>/stock/<종목>`, `#/runs/<id>/report`은 이 화면의 해당 탭을 연 상태로 연다(기존 주소 유지).

### 8.3 목표로 전략 찾기 (2열)

- 왼쪽: `1 목표`(목표 승률, 최소 거래 수) · `2 탐색 범위`(패턴·결합·손절·익절·보유 토글) + 아래 고정 영역(시도할 후보 수, 예상 시간, 상한 초과·범위 오류, 탐색 실행).
- 오른쪽: 탐색 전 안내 → 진행 → 후보 표(선택 구간 성과 · 평가 구간 성과 · 3중 검증, 시도한 후보 수). 승률만으로 순위를 매기지 않는다. 평가 구간은 고르는 데 쓰지 않았다고 표 아래에 밝힌다.

### 8.4 저장한 전략 · 백테스트 기록 (1열)

- 저장한 전략: 전략마다 카드(이름, 저장일, 패턴·청산·대상 요약, 불러오기·삭제).
- 백테스트 기록: 표(실행 시각 · 전략 · 상태 · 걸린 시간 · 실행 ID · 열기 · 삭제). 삭제 열의 휴지통을 누르면 같은 칸에 "삭제할까요? [삭제] [취소]"(초점은 취소). 진행 중인 실행은 버튼 비활성. 서버는 `DELETE /api/runs/{id}`로 파일을 `runs/.deleted/`에 옮긴다(되살릴 수 있음, E20).

### 8.5 공시·뉴스 검색 · 목록 · 영향 분석 (2열)

- 검색: 위에 as_of(KST)·검색어·출처, 아래 목록. 오른쪽에 자료 상세. "as_of 이전에 볼 수 있던 자료만" 문구를 숨기지 않는다.
- 비슷한 제목 묶음은 "비슷한 제목 n건 (글자 유사도)"로 쓰고 같은 사건이라 단정하지 않는다.
- 제품은 제목·회사명만 보관·표시한다. 원문은 출처 링크로만 연다.
- 시각은 시간대를 붙여 파싱하고 KST로 표시한다(문자열을 잘라 쓰지 않음).
- 목록: 왼쪽 조건·수집 상태·목록·쪽 넘김, 오른쪽 자료 상세. 줄이나 제목을 누르면 주소를 바꾸지 않고 오른쪽에 연다. `#/archive/doc?id=…`로 들어오면 같은 as_of·mode의 목록과 그 상세를 함께 연다.
- 영향 분석: 왼쪽 조건·모델 정보, 오른쪽 [가중치 | 사건·차트] 탭(종목을 넣고 조회하면 사건·차트가 먼저). 모델이 없거나 오류면 탭 없이 상태만.
- 영향 분석은 결과 없음 4종(`no_model` · `no_events` · `coverage_gap` · `data_unavailable`)을 각각 다른 문장으로 보인다.

### 8.6 봉 예측 (2열)

- 왼쪽 종목·봉 단위(1시간 / 3시간), 오른쪽 차트: 지난 종가 선 + 다음 n봉 회색 구간(분위 0.1–0.9). 가운데 분위선과 예상 캔들은 그리지 않는다.
- 표시 방향은 `상승 쪽 / 하락 쪽 / 불확실`과 상승 확률. 차트 바로 아래 고정 문구 **"과거 데이터로 계산한 통계적 예상 범위이며 실제 가격 전망이나 매매 신호가 아닙니다."**(E17)
- 채점 차이 같은 손익이 아닌 수치에는 빨강·파랑을 쓰지 않는다.
- 화면 구현은 P2-10(담당 Seonghwanaa) 범위다. 이 문서는 시각 규칙만 정한다.

### 8.7 시장 브리핑 (1열)

- 발행 전에는 `준비 중` 상태와 생성 방식(기준 시각 하루 1회, AI 입력은 집계 수치만 — D-7 v1)을 보인다. 기사 제목·링크는 근거 목록으로만 보인다.

### 8.8 로그인 · 비밀번호 재설정 (v1 §6.1 유지)

- 메뉴·상단바 없는 화면. 토큰·서체·모서리는 이 문서를 따른다. 데모 모드·Supabase 모드 문구와 계정 존재를 드러내지 않는 오류 문구 규칙은 그대로 둔다.

## 9. 차트

- 라이브러리: 기존 ECharts(`web/vendor/echarts.min.js`). 새 라이브러리를 들이지 않는다.
- 색은 `getComputedStyle(document.documentElement)`로 CSS 토큰(`--text`, `--muted`, `--line`, `--up`, `--down`, `--accent`, `--amber`, `--shade-*`, `--band*`)을 읽어 넘긴다. 테마가 바뀌면 열린 차트를 새 색으로 다시 그린다.
- 열 폭이 바뀌면(조절바·자리 바꾸기·서랍·창 크기) 차트 크기를 다시 맞춘다(`ResizeObserver`).
- 축·단위·기간·범례·데이터 기준일을 차트 가까이에 둔다. 툴팁은 날짜·값·단위·시리즈 이름.
- 매수 ▲ `--up`, 매도 ■ `--down`, 상승 국면 `--shade-up`, 하락 국면 `--shade-down`, 횡보는 음영 없음. 모양으로도 구분한다.
- 선 굵기: 주 시리즈 1.5px, 비교 시리즈 1px 점선. 장식용 그래프와 분석 그래프를 같은 모양으로 그리지 않는다.

## 10. 접근성·품질 기준

### 10.1 접근성

- 키보드만으로 메뉴, 모든 입력·토글·버튼, 탭, 조절바, 자리 바꾸기, 서랍을 쓸 수 있다.
- 초점은 2px `--accent` 외곽선으로 보인다.
- 색만으로 상태를 전하지 않는다(§2.3).
- 글자 대비 4.5 이상(§2.2). 장식 요소는 `aria-hidden`.
- 서랍이 열리면 초점을 서랍 안 첫 입력으로 옮기고, 닫히면 연 버튼으로 돌려준다.

### 10.2 시각 QA 체크리스트

- [ ] 1920 · 1440 · 1366 · 1280 · 1100 · 768 · 375px에서 상단바 칸 경계 = 열 경계, 페이지 가로 넘침 0, 상단바 넘침 0, 탭·메뉴 글자 줄바꿈 0
- [ ] 실행 버튼(민트 바탕)은 화면에 하나다
- [ ] 다크·라이트 모두 §2.2 대비를 지킨다. 라이트에서 민트 글자·선이 없다
- [ ] 모든 수치에 단위·기간·거래 수 또는 데이터 상태가 있다
- [ ] 실행 없음 · 실행 중 · 실패 · 분석 대상 아님 · 표본 부족 상태가 일반 결과와 구분된다
- [ ] 예측이 회색 구간과 방향으로만 보이고 고정 문구가 붙는다
- [ ] 비권유 고지가 모든 화면에서 보인다
- [ ] 조절바·자리 바꾸기·테마가 새로고침 뒤에도 유지되고, 저장소가 막힌 브라우저에서도 기본값으로 동작한다

## 11. 구현 인계

- 토큰 이름은 §2–§4의 CSS 변수 이름을 그대로 쓴다. 기존 `app.css` 변수와의 대응:

| 기존 | 새 이름 | 비고 |
|---|---|---|
| `--canvas` `--surface` `--control` `--line` `--text` `--muted` `--mint` `--mint-ink` `--amber` `--up` `--down` `--error` | 같은 이름 | 값만 §2.1로 |
| `--red` / `--blue` | `--up` / `--down` | 옛 별칭, 쓰는 곳을 옮긴 뒤 삭제 |
| `a { color: var(--mint) }`, 포커스 `rgba(136,230,188,.78)` | `--accent` | 라이트 대비 때문 |
| `--shadow` `0 18px 45px …` | `--shadow` (§2.1) | 그림자는 서랍·알림에만 |
| (없음) | `--hover` `--sel` `--line-strong` `--dim` `--prose` `--accent` `--mint-line` `--warn-line` `--err-line` `--hatch` `--hatch-key` `--shade-*` `--band*` `--scrim` | 새로 추가 |

- `web/design-tokens.json`은 `color.dark`, `color.light`, `type`, `space`, `size`, `layout` 묶음으로 이 문서 값을 그대로 옮긴다.
- 화면 문구는 `i18n.js` 키로만(한국어·영어). 새 문구(자리 바꾸기·조절바·테마·서랍 라벨)도 키로 추가한다.
- 화면은 API JSON만 표시한다. 시안에 있지만 지금 API로 만들 수 없는 동작은 구현 명세(`/srs`)에서 제외·후속으로 따로 적는다.
