### S1. F1 원본 데이터 팀 공유 — 데이터 서버 API [확정 2026-10-12: F1a]

> **개정 (2026-10-14, F1d):** 팀원 PC 로 원본을 동기화하지 않는다. 동기화는 데이터 서버 PC 안에서만 쓰고(S8·S9), 팀원 PC 재현(F1.3)은 보류. 아래 내용은 서버 PC 기준으로 읽는다.

- **브랜치:** `feat/F1-data-server-sync`
- **방식 (확정):** `Seonghwanaa` 데이터 서버 API로 공유합니다. 엔진의 데이터 읽기(`engine/src/regime_lab/data/loader.py`)는 **바꾸지 않습니다.** 대신 데이터 서버 API에서 받아 **기존 store Parquet 형식 그대로** 로컬에 저장하는 동기화 스크립트를 둡니다. 백테스트·예측·근거 검색 코드는 그대로 동작합니다.
- **변경 파일:**

| 파일 | 역할 | 내용 |
|---|---|---|
| `engine/scripts/sync_data_server.py` (신규) | 인프라 스크립트 | 표준 라이브러리 `urllib.request`(리디렉션 금지, 시간 제한, 응답 크기 상한) + 엔진 기존 의존성 `pyarrow`. 받은 데이터를 `prices.parquet`·`marketcap.parquet`·`master.parquet`·`index.parquet`·`delisted.parquet`·`raw/krx_daily/*.parquet`·`raw/sector/*.parquet`와 **같은 열·형식**으로 새 폴더에 저장. 1분봉은 기존 1단계 사본 형식·매니페스트(`data/minutes.py`가 읽는 형식)로 저장 |
| `engine/tests/test_sync_data_server.py` (신규) | 테스트 | 가짜 서버 응답(합성)으로 열·자료형 검사, 실패 시 부분 파일이 남지 않음, 인증값이 오류 문구·로그에 나오지 않음 |
| `README.md` "처음 한 번" | 문서 | 환경변수 설정 → 동기화 → `paths.local.yaml`의 `store` 전환 → `regime-lab prepare` 절차 |

- **규칙:**
  - 서버 주소·인증값은 환경변수 `REGIME_DATA_API_URL`·`REGIME_DATA_API_TOKEN`으로만 받습니다. 저장소·문서·로그·PR에 실제 값을 적지 않습니다. 인증값은 읽기 전용 권한만 갖게 합니다.
  - 원본 `store`를 덮어쓰지 않습니다. 새 폴더에 `.tmp`로 받고, 검증을 통과한 뒤 한 번에 이름을 바꿉니다. 전환은 사용자가 `paths.local.yaml`에서 합니다.
  - 검증: 열 이름·자료형이 기존 형식과 같은지, 행 수가 서버가 알려 준 수와 같은지 봅니다. 기존 store가 있으면 겹치는 구간의 값이 같은지도 비교합니다(`fetch_index_history.py`의 겹침 검사 방식). 어긋나면 저장하지 않습니다.
  - 준비 캐시는 `input_file_hashes`(크기·수정 시각)로 자동 무효화됩니다. 이 동작을 테스트로 확인합니다.
- **산출물:**
  - **F1.1 서버 API 문서:** 저장소의 `docs/` 문서에 경로 목록, 응답 형식, 인증 방식, 요청 한도, 접근 가능한 네트워크 조건을 적습니다. 실제 주소·토큰은 적지 않습니다.
  - **F1.2 안내:** 위 README 절차와 파일별 크기·지문 확인 방법
  - **F1.3 재현 — 보류 (2026-10-14 결정 F1d, 원본은 서버 PC 만):** 팀원 PC 1대에서 동기화 → engine 테스트(`data` 마커 포함) → `prepare` → `forecast-run --timeframe 1h --sample` 결과 줄을 기록합니다.
- **같이 확인할 것 (`hchee99` 종목 연결, 결정 P3-8.3a):** 동기화한 `master.parquet`에 `ticker`·`name` 열이 있는지 확인하고 F1.2에 적습니다.
- **범위 밖:** 공시 `ext_store`는 서버에 올리기 전까지 파일 사본으로 공유합니다(F1a). 엔진이 서버를 직접 조회하도록 loader를 바꾸는 것도 이번 범위 밖입니다.

### S8. X11 앱 서버 설치·첫 변환·자동 시작 [확정 2026-10-14: F1b ①②]

- **구역:** 서버 PC 설정 + 데이터 서버 폴더. 팀 저장소 변경 없음 ([F1 문서](F1_데이터_서버_API.md) §6.2)
- **내용:**
  1. 서버 PC 에 저장소(develop)를 받고 `uv sync --project engine`·`uv sync --project api`
  2. `REGIME_DATA_API_URL=http://127.0.0.1:8100` 으로 `sync_data_server.py --out <새 폴더>` → `paths.local.yaml` 의 `store` 전환 → `regime-lab prepare`
  3. 앱 시작 파일을 데이터 서버 폴더에 두고(데이터 API 의 `run_server_task.bat`·`ops_autostart.ps1` 방식) 작업 스케줄러에 등록합니다. `REGIME_HOST`·IP 허용 목록 값은 이 시작 파일의 환경변수로 둡니다(저장소에 쓰지 않음).
  4. 앱 포트 방화벽은 같은 망만 엽니다.
  5. **기사:** 받는 쪽은 PR #81(hchee99)로 정해졌습니다(결정 F1c 개정, X11.4 취소). #81 병합 뒤 서버 앱 시작 파일에 `REGIME_DATA_API_URL=http://127.0.0.1:8100`·`REGIME_NEWS_REFRESH=1` 을 넣습니다. 팀원 PC 는 켜지 않습니다(F1d).
- **완료 기준:** 서버 PC 에서 loopback 으로 실행·결과·근거 검색 화면 정상, 재부팅 뒤 자동 시작, 앱 + MariaDB 메모리 최대치 기록
- **멈추고 물을 것:** 서버 RAM 이 부족해 앱과 DB 를 함께 돌리기 어려울 때 (F1b ② 재결정)

- **주의:**

  - 실패하면 전환하지 않고 이전 폴더로 계속 서비스하며, 실패 기록을 남깁니다.
  - 앱 재시작 때 진행 중이던 작업은 `server_restarted` 로 실패 처리되므로 새벽 시각으로 잡습니다.
- **데이터 버전 [확정 2026-10-14: F1d ②]:** 받은 폴더마다 표별 행 수·내용 해시를 적은 지문 파일을 남깁니다(S8 첫 변환도 같음).

- **멈추고 물을 것:** 동기화 스크립트의 검증·폴더 규칙을 바꿔야 할 때
