## 2. 해결한 문제와 근거 구분

최초 문제 인지는 사용자가 제공한 웹 검색 결과. 당시 서버·기준 시각·모드·종목 필터·문서 지문이 미기록 상태였으므로, 이후 기존 로컬 자료를 고정하여 현행 엔진으로 별도 재현. 표시 점수는 이전 웹 보고와 일치했으나 두 실행 환경의 동일성까지 증명한 것은 아님.

| 문제 | 변경 전 직접 확인 | 원인 |
|---|---|---|
| 회사명 조각 오탐 | 대한전선 질의에서 한전기술이 4위, 점수 7.344979, 맞은 토큰은 한전뿐. 5위는 전선 산업 자료, 6.730804, 전선만 일치 | 대한전선의 2-gram인 대한·한전·전선 중 하나만 맞아도 후보 포함 |

| 복합 조건 누락 | 삼성전자 자사주 매입에 화성기지를 추가해도 상위 5개 대표·점수·similar 전체 동일 | 맞은 토큰의 점수만 합산하며 빠진 검색 조건을 후보 자격에 반영하지 않음 |
| 혼합 문자열 오탐 | 없는회사검증ZXQ987 질의에서 98만 맞는 무관 문서가 1위, 9.789907 | 한글이 섞인 전체 덩어리를 2-gram으로 분해하여 zx·xq·q9·98·87까지 생성 |

화성기지 전체 문자열은 색인 대상 필드에서 0건이었지만 성기 조각은 1건, 기지 조각은 7건에 존재. 전역 토큰 존재 여부나 모든 조각의 개별 존재만으로 완전 조건 충족을 판정할 수 없는 근거.

## 3. 평가 도구·시점 검증 보완

### 3.1 평가 입력·채점

| 항목 | 최종 동작 |
|---|---|
| 평가셋 구조 | 배열·객체 구조, 고유하고 비어 있지 않은 ID, dev/test 표기 검사 |
| 선택 분할 | 선택된 분할의 질의·시간대 포함 as_of·정답 배열·종목 필터·유형·관련도·사건 라벨 구조를 검색 전에 검증. 선택 분할 0문항은 오류 |
| 다른 분할 | ID·분할 표기는 검사하되 dev 실행에서 test 정답 내용은 검증·채점하지 않는 경계 유지 |
| 관련도 | grade=0은 비관련, 양수만 Recall·MRR·답 있음 판정의 정답. 음수·문자열·불리언·NaN·무한대·유한 DCG 이득 계산 불가 등급 거절 |
| 중복 정답 | 같은 문서를 URL/doc_id로 중복 표기하면 최고 양수 등급으로 통합. 입력 순서 무관 |
| 누락 정답 | 문서에 없는 양수 정답은 경고 후 찾지 못한 정답으로 계산. 지표를 높이기 위한 임의 제거 없음 |
| CLI 오류 | 정답 파일 누락·잘못된 JSON·인코딩 오류를 validation_failed·종료 코드 2로 처리 |

이 변경은 평가 신뢰성 보완이며, 검색 성능 향상 수치 자체는 아님. 변경 전 채점 결과와 비교할 때 평가기 버전·처리 차이 기록 필요.

### 3.2 시점·버전·캐시 검증

- observed는 first_seen_at·available_at 모두 기준 시각 이하, historical_assumed는 available_at 이하인 기존 규칙 유지.
- 같은 doc_id의 허용 버전 중 최신 버전 선택, 정정 공시는 별도 문서이며 관계 표시는 확정 관계가 아닌 후보라는 기존 계약 유지.
- 미래 문서·미래 버전·입력 순서 변경 전후 과거 문서·점수·순위·similar·visible_docs 불변 검증.
- BM25의 IDF·평균 길이도 해당 시점에 보이는 문서 집합으로 계산. 미래 문서 통계를 섞는 방식 제외.
- 캐시 사용·미사용 결과 일치, 문서 지문·설정·색인 버전 변경 시 새 색인 키 사용 확인.
- 전체 문서 수·문서 지문은 미래 자료 추가로 달라질 수 있는 감사 메타데이터. 과거 검색 결과 불변 항목과 구분.

삭제·만료 정책은 이번 개선으로 확정하거나 확대하지 않은 영역. 기존 행 제외 동작 검증을 문서 전체 삭제·자동 만료 완료로 해석하지 않는 기준.

## 4. 최종 검색 규칙

### 4.1 조건 검사와 점수 계산 분리

처리 순서:

1. 입력·기준 시각·모드·종목 필터 검증.
2. 기준 시각에 보이는 최신 허용 버전과 명시 종목 필터로 문서 집합 구성.
3. NFKC·영문 소문자 정규화, 질의 단위를 조건으로 구성.
4. 보이는 문서 집합으로 BM25 통계·점수 계산.
5. 점수가 있는 문서마다 모든 조건의 원형 또는 허용 조사 변형 충족 여부 검사.
6. 적격 문서만 정렬·후보 수 제한·비슷한 제목 묶기 또는 MMR 적용.
7. 기존 응답 형식으로 반환. 적격 결과가 없으면 no_evidence.

조건 사이에는 AND, 같은 조건의 원형과 허용 조사 변형 사이에는 OR 적용. 회사명·주제 일부가 맞았다는 이유로 남은 조건을 삭제하거나 부분 일치로 자동 완화하지 않는 동작.

한 조건을 두 문서나 두 필드의 조각으로 조립하는 처리 금지. 서로 다른 조건은 같은 문서의 제목·회사명에서 각각 충족 가능. 후보 수를 먼저 제한해 뒤의 적격 문서를 놓치는 처리도 제외.

### 4.2 조사·공백·식별자 경계

| 구분 | 최종 규칙·예시 |
|---|---|
| 지원 조사 | 이/가·은/는·을/를·과/와. 받침 규칙에 맞는 결합만 1회 분리 |
| 기본어 증거 | 분리 후 최소 2글자. 대상 문서의 독립 단어 또는 허용 조사 결합 형태로 확인 |
| 공통 종목 처리 | 삼성전자가→삼성전자, 대한전선은→대한전선, SK하이닉스가→SK하이닉스. 예시 종목 전용 분기 없음 |
| 잘못된 분리 방지 | 국가→국, 전문가→전문, 대한전선→한전 불허 |
| 공백 차이 | 대한전선↔대한 전선, 자사주매입↔자사주 매입, 2분기↔2 분기 허용 |
| 중간 내용 | 자사주매입↔자사주 계획물량 매입, 화성기지↔화성 사업 기지 불허 |
| ASCII 식별자 | HBM3E↔hbm3e양산 허용, HBM3E↔HBM3E2·XHBM3E 불허. 별개의 HBM 3E를 연결하지 않음 |
| 숫자 부분 | 987↔98·1987·9870 불허 |
| 점수 토큰 | 한글 연속 구간만 2-gram, ASCII 영숫자 연속 구간은 그대로 유지. HBM3E양산→hbm3e·양산, 2분기→2·분기 |
| 빈 조건 | 구두점뿐인 입력은 조건 0개를 모두 충족한 것으로 취급하지 않고 no_evidence |

원형은 복합어 내부의 완전 문자열을 찾을 수 있는 방식. 조사 분리 대안에는 독립 단어 경계를 추가 적용. 완전 문자열의 존재가 동일 법인·회사 관련 사실의 확정 판정을 뜻하지는 않는 한계.

## 7. 지연 측정

동일 고정 9질의 각각 15회, 전후 각각 135회 직접 엔진 호출. 색인 준비 제외. p50은 중앙값, p95는 정렬 표본의 floor((n−1)×0.95) 위치 값. 제품 평가기의 보간 percentile과 같은 산식이라고 단정하지 않는 기준.

| 지표 | 변경 전 | 변경 후 |
|---|---:|---:|
| p50 | 16.79ms | 13.14ms |
| p95 | 21.07ms | 16.95ms |

점수가 있는 행만 완전 조건 검사하여 전체 문서 반복 정규화를 피하고, 부적격 문서를 묶기 전에 제외하는 구현 적용. 위 측정만으로 개별 최적화의 기여도를 분리하거나 모든 질의·서버의 속도 개선을 보장하지 않는 한계.

최종 변경 후 측정은 전체 회귀 종료 뒤 수행. 측정 JSON은 문서 지문·질의·상태·문서 식별자·점수·토큰·지연 요약이며 기사 제목·본문 원문은 저장하지 않은 산출물.
