## 1. 개요

### 1.1 목적

본 문서는 다음 두 기능을 하나의 **과거 데이터 기반 분석 서비스**로 정의한다.

1. 사용자가 선택한 매매 패턴을 코스피·코스닥 종목의 일봉 데이터로 백테스트하고, 시장 국면·시장·시가총액 그룹별로 성과를 분해한다.
2. 야간 글로벌 시장 변화와 뉴스·테마 입력을 분석 근거로 제시하고, 과거 조건부 성과를 포함한 개장 전 브리핑을 생성한다.

이 문서는 시스템이 해야 하는 일을 정의한다. 구현 상세는 별도 설계·인수인계 문서에서 관리한다. 모든 화면과 결과는 과거 데이터 분석이며 투자 권유가 아니다.

### 1.2 통합 및 범위 결정

두 원본 명세의 충돌은 아래 결정으로 해소한다.

| 쟁점 | 최종 결정 | 이유 |
|---|---|---|
| 주식 백테스트 시간 단위 | 국내 주식 전략의 신호·진입·청산·성과 계산은 일봉만 사용 | 기존 프로젝트의 C-2 및 재현성 유지 |
| 야간 5분봉 | 야간 선물·환율의 충격 시점 탐지에만 사용하며, 국내 주식 장중 체결 백테스트에는 사용하지 않음 | MarketPulse의 시장 충격 분석은 지원하되 1분봉·장중 매매 범위는 제외 |
| VWAP 눌림목 | `VWAP_20` 등 전일 확정 기술지표를 이용한 일봉 조건부 분석만 제공 | 09:10~09:40 장중 눌림목 체결 전략은 일봉 전용 제약과 충돌하므로 본 릴리스에서 제외 |
| AI/ML | LLM은 해설·구조화 전략 변환만 수행하며 수치·순위·신호를 결정하지 않음. ML은 과거 거래의 선택적 필터 실험으로만 허용 | 가격 예측·자동 추천·파라미터 최적화를 방지 |
| 외부 시장·뉴스 데이터 | 시연에서는 표준화된 파일/어댑터와 허가된 샘플만 사용. 실시간 상용 데이터 수집·계약은 제외 | 데이터 권한·운영 위험을 범위 밖으로 유지 |
| 종목 노출 | 종목 추천 대신, 검증된 과거 조건을 충족한 **분석 대상**과 표본·위험을 표시 | 비권유 원칙 준수 |

### 1.3 포함 및 제외

**포함**

- 코스피·코스닥 일봉 데이터 수집·정제·유니버스 구성
- 고정 파라미터 패턴 10종, 백테스트, 시장/종목 국면 분석
- 비용·체결 제약·미래참조 방지·기간 분할·무작위 벤치마크 검증
- 야간 시장 충격·뉴스·국내 테마 입력의 검증 및 조건부 브리핑
- 대시보드, LLM 보고서·자연어 전략 변환·제한적 개선 루프
- 선택적 ML 거래 필터 실험

**제외**

- 실시간 주문, 증권사 API 연동, 매수·매도 지시, 목표가·비중 제안
- 국내 주식 1분봉 또는 장중 체결 기반 백테스트
- 가격 예측 모델, 파라미터 최적화·그리드 서치
- 유료 외부 데이터 계약, 실시간 뉴스 크롤링, 텔레그램·문자 발송, 운영 스케줄러 배포
- 펀더멘털 필터, 모바일 앱, 결제·구독 기능

### 1.4 용어

| 용어 | 정의 |
|---|---|
| 패턴 | 고정 파라미터의 일별 매수 조건. 예: RSI(14)가 30을 상향 돌파 |
| 전략 | 패턴 조합(AND/OR), 청산 규칙, 대상·기간으로 구성된 실행 단위 |
| 국면 | 200일선 위치와 20일 기울기로 판정한 상승(bull)·횡보(sideways)·하락(bear) 상태 |
| 시장 충격 | 야간 선물·환율·글로벌 지수의 기준선 대비 비정상 변동 구간 |
| 테마 가중치 | 충격 이벤트와 국내 테마의 관련도·방향성을 수치화한 분석값 |
| 분석 대상 | 검증을 통과한 과거 조건에 부합하는 종목. 추천·매매 지시가 아님 |
| 미래참조 | 기준일 이후 정보를 신호·국면·결과에 사용하는 오류. 절대 금지 |
| 워밍업 | 지표 계산을 위해 백테스트 전 확보하는 최소 250거래일 구간 |

## 2. 제품 및 운영 제약

### 2.1 사용자

| 사용자 | 목적 |
|---|---|
| 일반 사용자 | 알려진 매매 기법 및 시장 조건의 과거 성과 확인 |
| 평가자 | 검증 설계·AI 활용 경계·재현성 평가 |
| 팀원 | 데이터·엔진·화면·ML 모듈 개발 및 테스트 |

### 2.2 운영 환경

- Python 3.12, pandas, numpy, pandas-ta, pyarrow 및 웹 UI 런타임을 사용한다. (2026-09-22 3.11에서 변경. `pandas-ta`는 호환 확인 후 사용하며, 비호환 시 지표를 직접 구현해 `test_indicators`로 검증한다.)
- 개발·시연은 메모리 8GB 이상의 개인 노트북에서 수행한다.
- 원본 시세 및 외부 뉴스 원문은 저장소에 커밋하지 않는다.
- LLM API 키는 환경변수로만 주입한다.

### 2.3 공통 제약

| ID | 제약 |
|---|---|
| C-1 | 개발 기간은 2026-09-21부터 2026-10-21까지이며 팀은 4인이다. |
| C-2 | 국내 주식 전략의 백테스트는 일봉만 사용한다. |
| C-3 | 패턴 및 청산 규칙의 파라미터는 코드·전략 파일에서 고정하며 UI 최적화·그리드 서치를 제공하지 않는다. |
| C-4 | LLM은 수치 계산, 국면 판정, 종목·패턴 순위를 결정하지 않는다. |
| C-5 | 목표가, 비중, 종목 추천, 주문 또는 매매 권유를 출력하지 않는다. |
| C-6 | KRX 수집 호출 간격은 0.4초 이상으로 제한한다. |
| C-7 | 야간·뉴스 데이터가 없거나 검증에 실패하면 브리핑을 생성하지 않고 상태와 사유를 표시한다. |

우선순위는 **M**(Must), **S**(Should), **C**(Could)로 표시한다.

| FR-D2 | KOSPI·KOSDAQ 지수 일봉과 종목 마스터(코드·이름·시장·업종·상장일·종목유형)를 저장한다. | M |

| FR-G2 | 야간 시장 시계열은 5분 이하가 아닌 집계 구간을 사용하며, 타임스탬프·출처·거래일·누락·중복을 검증한다. | M |
| FR-G3 | 시스템은 고정된 기준선·임계값으로 야간 충격 구간과 충격 점수를 산출하며, 산출 근거 시계열을 보존한다. | M |
| FR-G4 | 뉴스 이벤트는 허가된 입력의 제목·발생 시각·출처·테마 관련도·방향성으로 저장한다. 원문 전문은 저장하지 않는다. | M |
| FR-G5 | 시스템은 충격 점수와 뉴스·테마 관련도를 결합해 테마별 분석 가중치와 상위 3개 테마를 산출한다. | M |
| FR-G6 | 뉴스·야간 데이터가 없거나 품질 검증에 실패하면 테마 순위·브리핑 대신 `데이터 부족` 또는 `검증 실패` 상태와 사유를 반환한다. | M |
| FR-G7 | 실제 데이터 공급사 연동은 교체 가능한 어댑터 범위로 제한하며, 시연용 샘플 입력으로 전 기능을 검증할 수 있어야 한다. | S |

### 3.3 패턴 및 전략 (FR-P)

| ID | 요구사항 | 우선순위 |
|---|---|---|

| FR-P2 | 각 패턴은 한 종목의 OHLCV를 입력받아 날짜별 매수 신호를 반환하는 동일 인터페이스를 구현한다. | M |

| FR-P5 | SMA·RSI·볼린저·전일 확정 `VWAP_20`의 참조 값은 수기 계산과 일치해야 한다. | M |

| FR-E4 | 왕복 거래비용(기본 0.30%, 전략 실행 설정에 기록)을 손익에서 차감한다. | M |
| FR-E5 | 각 거래에 단순 보유 수익률, 초과수익, 진입 당시 시장·종목 국면·시총그룹·유동성그룹·업종을 기록한다. | M |
| FR-E6 | 전략 B 분석은 전일 확정 `VWAP_20`, 야간 테마 가중치, 일봉 진입·청산 규칙에 근거한 과거 조건부 성과만 계산한다. | M |
| FR-E7 | 백테스트 결과에는 기간·거래수·승률·평균·중앙값 수익률·평균 초과수익·손익비·샤프·MDD·비용·제외 거래 수를 포함한다. | M |
| FR-E8 | 백테스트는 워밍업 기간 중 거래를 만들지 않으며, 각 실행을 고유 `run_id`와 설정·데이터 기준일·입력 버전으로 저장한다. | M |
| FR-E9 | 참조 예제(TSLA 2025H1, 10/30 골든크로스, 손절 8%, 익절 20%)의 결과를 +3.6% ±0.1%p로 재현한다. | M |

### 3.5 집계 및 검증 (FR-A)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-A1 | 거래를 국면 × 시장 × 시총그룹으로 집계해 거래수·승률·평균/중앙값 손익·평균 보유수익·평균 초과수익·손익비를 산출한다. | M |
| FR-A2 | 거래 300건 미만 셀은 `표본 부족`으로 표시하고 결론·분석 대상 선정에 사용하지 않는다. | M |
| FR-A3 | 2024-02-29 기준 전반·후반으로 나눈 성과 순위의 유지·약화·역전을 판정한다. | M |
| FR-A4 | 실제 거래와 같은 횟수·보유기간으로 진입일을 무작위 추출한 1,000회 시뮬레이션과 실제 초과수익의 백분위를 제공한다. | S |
| FR-A5 | 다수 전략을 평가할 때 Benjamini-Hochberg FDR(q ≤ 0.10)를 적용하며, 기간 분할·FDR·무작위 벤치마크를 모두 통과하지 못한 전략은 분석 대상에서 제외한다. | M |

### 3.6 브리핑·사용자 인터페이스 (FR-U)

| ID | 요구사항 | 우선순위 |
|---|---|---|

### 3.8 Unity Web UI·실행 연동 및 유사 패턴 비교 (FR-X)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-X1 | Unity Web UI는 로그인, 전략 빌더, 실행 진행, 결과, 종목 상세, AI 보고서 패널을 공통 헤더·사이드바 안에서 전환한다. 로그인은 UI 흐름만 제공하며 실제 인증 연동은 별도 범위다. | M |
| FR-X2 | 분석 실행은 조건 JSON을 API에 전송하고 `run_id`를 받은 뒤 상태·결과·취소 API를 조회하는 비동기 방식으로 동작한다. Unity 클라이언트는 Python의 로컬 파일 경로를 직접 읽거나 분석을 직접 실행하지 않는다. | M |
| FR-X3 | 실행 진행 화면은 서버가 제공한 단계, 처리 종목 수, 전체 종목 수, 경과 시간, 완료·실패·취소 상태를 표시한다. 화면 애니메이션만으로 완료를 판정하지 않는다. | M |
| FR-X4 | 결과·종목 상세·AI 보고서 화면은 실행 결과 없음, 데이터 없음, 표본 부족, 네트워크 실패, 서버 실패, 취소 상태마다 원인·복구 행동·전 화면 이동 수단을 제공한다. | M |
| FR-X5 | 전략 입력값은 API 전송 전과 서버 수신 시 모두 검증한다. 날짜는 `YYYY-MM-DD`, 거래대금은 원, 보유기간은 거래일 수, 퍼센트는 단일 단위로 고정하며 미사용 trailing stop은 `null`로 전달한다. | M |
| FR-X6 | 화면의 모든 성과 수치·차트·AI 보고서 수치는 동일한 `run_id`의 결과에서만 파생하며, 지표명·계산식·단위를 조회 가능하게 표시한다. | M |
| FR-X7 | 유사 패턴 비교는 현재 관측 구간과 과거 유사 구간·그 이후의 **실제 과거 데이터**를 정규화된 공통 축으로 보여준다. 반환값에는 비교 기간, 유사도, 정규화 방식, 데이터 기준일을 포함한다. | S |
| FR-X8 | 유사 패턴의 과거 후속 움직임은 예측값으로 표시하지 않는다. 관측 구간, 유사 과거 구간, 과거 후속 결과를 색·선 종류·범례·고지로 구분한다. | M |
| FR-X9 | 3D 차트는 다수 과거 사례의 깊이·선택 비교가 이해를 돕는 경우에만 사용한다. 핵심 수치표·전략 성과·입력 UI는 2D 평면 UI로 표시한다. | S |

## 7. 최소 변경 구현 계획

1. 기존 데이터·국면·패턴·백테스트 모듈이 최종 데이터 계약과 결과 메타데이터를 충족하도록 정렬한다.
2. 야간 시장·뉴스·테마 입력 검증과 충격·테마 가중치 계산을 독립 모듈로 추가한다.
3. 일봉 기반 전략 B 조건부 백테스트와 3중 검증 연결을 추가한다.
4. Unity Web UI와 분석 API 간 실행·상태·결과·취소 데이터 계약 및 실패 상태를 구현한다.
5. 브리핑·전략·검증·유사 패턴 결과를 대시보드에 비권유 형태로 노출한다.
6. 미래참조, 외부 입력 품질, 브리핑 재현성, 실행 API 계약, 고지 노출 테스트를 추가하고 전체 회귀를 실행한다.
