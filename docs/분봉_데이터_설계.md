1분봉 원본을 읽기 전용으로 실사한 결과(P2-1)와, 그 결과에 맞춘 정규화 규칙·저장 위치·캐시 무효화·모듈 위치 제안(P2-3)이다. 모듈 위치는 G2 2차(`AGENTS.md` §2·§4 개정)의 입력이다.

- 담당: Seonghwanaa · 관련 WBS: P2-1, P2-3 (다음: P2-2 예측 출력 결정 D-2, P2-4 분봉 로더·시간봉 집계)
- 근거: [SRS v2.0](SRS.md) §1.2·§4·FR-F1~F7, [plan/02-multiframe-forecast.md](plan/02-multiframe-forecast.md) 작업 ④, 결정 E17(예측 표시), C3(Parquet + DuckDB 유지)
- 상태: P2-1 **완료**(2026-10-01). P2-3·D-2(§5) **제안**(팀 리뷰 중).

### 1.3 가격 기준·거래량·거래대금

- **가격 기준이 섞여 있다.** `store` 수정주가 ÷ KRX 원주가 비율이 2% 넘게 바뀐 종목(가격 조정 이벤트) 1,248개 중, 수정주가≠원주가인 날의 분봉 종가가 원주가와 같은 종목 816개, 수정주가와 같은 종목 133개, 섞인 종목 47개. 이벤트 날짜로 나뉘지 않는다(종목별 사후 수정으로 보임, 원인 미확인).
- 정규장 분봉을 일로 합친 종가 = KRX 원주가: 2026-04-24 전 95.2%, 이후 99.25%.
- **`value`는 당일 누적 거래대금(원)**이다. 첫 행 = 가격×거래량(중앙값 1.00), 값이 줄어든 적 0, 마지막 값 ÷ KRX 일 거래대금 중앙값 0.999.
- **2026-04-24부터 KRX+NXT 통합 시세**로 보인다. 장외 시간 행이 있는 종목의 정규장 거래량 ÷ KRX 일 거래량 상위 10%가 1.43배(장외 행 없는 종목은 1.00배), 고가·저가 일치율 97.6%(장외 행 없는 종목 99.97%). 거래소 구분 컬럼이 없어 분리할 수 없다.

## 2. 정규화 규칙 (P2-3.1, 제안)

원본은 덮어쓰지 않는다. 아래 규칙은 정규화 단계(§3의 2단계)에서만 적용한다.

| # | 대상 | 규칙 | 근거 |
|---|---|---|---|
| N1 | 세션 | **정규장 09:00~15:30만** 사용한다. 장외 시간(08:00~08:59, 15:31 이후)은 제외한다. 늦은 개장일은 있는 행 그대로 둔다(10:00 시작) | 장외 시간은 2026-04-24 이후에만 있어 기간 일관성이 없다(§1.2) |
| N2 | 가격 기준 | 종목별로 장 마감 후 그날 정규장 집계 종가를 KRX 원주가·`store` 수정주가와 대조(허용오차 0.2%)해 `price_basis`를 `raw`·`adj`로 판정한다. 둘 다 아니면 그 종목·일을 제외하고 사유를 남긴다. **판정은 다음 거래일 09:00부터 사용**하고(§2.2), 당일 장중 입력에는 전 거래일까지의 판정을 이어 쓴다 | §1.3. 판정에 당일 종가가 필요해서 당일 장중에는 알 수 없다 |
| N3 | 가격 조정 | **입력**: 같은 가격 기준 구간 안의 수익률로 만든다. 조정 이벤트(`store` 수정주가 ÷ 원주가 비율이 바뀐 날)를 넘는 창은 as_of에 이미 확정된 비율(이벤트 다음 거래일 09:00부터)로만 이어 붙인다. 조정 비율과 이벤트 여부는 특징으로 쓰지 않는다. **예측 대상 선정**: as_of에 알 수 있는 정보로만 정한다. 이벤트 당일이라는 사실은 그날 장중에 알 수 없으므로 **예측을 빼지 않는다**(사전 공시 일정은 데이터에 없음). **목표·채점**: 목표는 실현 수익을 사후 조정 비율로 고친 값(가짜 가격 점프 제거)이다. 이벤트 당일 표본은 빼지 않고 채점 결과를 "이벤트 당일 포함/제외" 두 가지로 함께 보고한다 | `store` 수정주가는 나중 이벤트까지 소급 반영돼 있어 비율·이벤트 여부를 입력이나 대상 선정에 쓰면 미래 정보가 들어간다. 목표는 원래 실현 뒤에 정해지는 값이라 사후 조정은 누출이 아니다 |
| N4 | 거래대금 | `value_1m` = 같은 종목·일의 **전체 행(장외 포함)** 을 시간순으로 정렬해 직전 행과의 `value` 차이로 계산한다(첫 행은 `value` 그대로). **N1 세션 필터보다 먼저** 적용한다. 원래 `value`는 `value_cum`으로 보존한다 | `value`는 장외 거래까지 포함한 당일 누적(§1.3). 예: 005930 2026-09-01은 장 전 50행이 있어, 정규장만 남긴 뒤 차분하면 09:00 1분 거래대금이 실제(가격×거래량)의 3.05배, 전체 행 차분이면 1.001배 |
| N5 | NXT 구간 | `nxt_period` = 날짜 ≥ 2026-04-24 플래그를 붙인다. 거래량 특징은 종목별 상대값으로 쓰고, 평가는 전후 구간을 나눠 보고한다 | 통합 시세로 거래량·고저가 성격이 바뀜(§1.3) |
| N6 | 결측 분 | 거래 없는 분을 0거래량 행으로 채우지 않는다. 집계 봉에는 실제 포함된 분 수 `n_minutes`를 남긴다 | 행이 없는 것이 원본 의미(§1.2) |
| N7 | 이상값 | 시가가 고가·저가 범위 밖인 106행, 세션 밖 행은 제외하고 개수를 지문에 기록한다 | §1.2 |
| N8 | 대상 종목 | `store` `master.kind = 보통주`만 기본 대상. 1분 예측 대상의 유동성 기준은 D-2 | 우선주 없음, 유니버스(U2)와 일치 |

### 2.1 집계 봉 경계 (FR-F1)

- 시간봉은 거래일 세션에 고정하고 날을 넘겨 묶지 않는다. OHLC = 첫 시가·최대 고가·최소 저가·마지막 종가, 거래량·`value_1m` = 합계.
- 길이가 다른 봉은 **합치거나 빼지 않고 그대로 둔다.** 마지막 봉을 합치면 1.5시간짜리 봉이 생기고, 빼면 종가가 빠지기 때문이다. 대신 봉마다 명목 길이 `bar_minutes`, 실제 포함 분 수 `n_minutes`, 하루 안 순번 `slot`을 남긴다. 모델은 `slot`을 특징으로 쓰고, 채점(P2-8)은 `slot`별로도 보고한다. 화면 x축은 봉 확정 시각을 쓴다.

| 봉 | slot | 구간 | 명목 길이 | 비고 |
|---|---|---|---|---|
| 1시간 | 1~6 | 09:00~09:59 … 14:00~14:59 | 60분 | |
| 1시간 | 7 | 15:00~15:30 | 31분 | 15:00~15:19 연속 매매 + 15:20~15:29 동시호가 + 15:30 종가 체결 봉 |
| 3시간 | 1 | 09:00~11:59 | 180분 | |
| 3시간 | 2 | 12:00~15:30 | 211분 | 동시호가·종가 봉 포함 |
| 늦은 개장일 (예: 10:00 개장) | 첫 봉 | 개장 시각부터 | 짧아짐 | slot 번호는 시각 기준으로 유지(1시간봉은 slot 2부터), `n_minutes`로 구분 |

- **15:20~15:29 동시호가**: 정규장에 포함해 마지막 봉에 넣는다. 이 구간에는 보통 체결 행이 없다(전체 기간 15,318행, 0.0%). **15:30 행**은 종가 단일가 체결이고 마지막 봉의 종가가 된다.
- 봉 확정 시각 = 봉의 마지막 분 + 1분(09:00~09:59 봉은 10:00, 마지막 봉은 15:31). 예측은 확정된 봉까지만 입력으로 쓴다(FR-F3). 진행 중인 봉은 쓰지 않는다(D-2, §5).
- 대표 종목·거래일의 수기 계산과 일치해야 한다(FR-F1, P2-4.4 테스트).

### 2.2 처리 순서와 이용 가능 시각 (as_of)

처리 순서(종목·일 단위): ① `(code, dt)` 정렬 → ② N4 `value_1m` 차분(전체 행) → ③ N7 이상값 제외 → ④ N1 정규장 필터 → ⑤ N2·N3 가격 기준·조정(전 거래일까지 확정된 값) → ⑥ §2.1 집계.

| 값 | 이용 가능 시각 (`available_at`) | 장중 as_of에서 |
|---|---|---|
| 1분봉 한 행 | 그 분의 다음 분 시작 (예: 09:00 봉 → 09:01) | as_of 이전에 끝난 분만 사용 |
| 집계 봉 | 봉 확정 시각(§2.1) | 확정된 봉만 사용 |
| `price_basis` 판정 (N2) | 판정일 다음 거래일 09:00 | 전 거래일까지의 판정 사용 |
| 조정 이벤트 비율·이벤트 여부 (N3) | 이벤트 다음 거래일 09:00 | 이벤트 당일에도 예측은 평소대로 함 (이벤트를 모르는 상태) |
| 일봉(`store`) 값 | 그날 장 마감 후 | 전 거래일까지 사용 |

- 검증(P2-4·P2-6): **장중 as_of 절단 불변**. as_of 이후의 1분 행, 당일 일봉, 이후 날짜 데이터를 지워도 그 as_of의 입력·예측이 같아야 한다(FR-F4).
- 합성 사례 테스트: 08:59/09:00 경계(장 전 누적 거래대금이 09:00 `value_1m`에 섞이지 않음), 판정이 바뀌는 날 다음 날부터 적용, 이벤트 당일. **as_of 이후 행을 지워도 예측 여부·실패 사유·예측 대상 표본 집합이 같아야 한다.**

## 3. 저장 위치·캐시 무효화 (P2-3.2, 제안)

| 단계 | 위치 | 내용 | Git |
|---|---|---|---|
| 0. 원본 | MariaDB `regime_lab.stock_minutes` (팀 데이터 서버) | 수정하지 않음 | – |
| 1. 원본 사본 | `data/minutes/stock_minutes_YYYYMM.parquet` + `minutes_manifest.json` | 원본 8컬럼 그대로, 월별, zstd (약 3.1GB). 매니페스트에 월별 행 수·최소/최대 시각·내보낸 시각 | 제외 (`/data/`) |
| 2. 정규화 캐시 | `cache/minutes/v<MINUTE_PREP_VERSION>_<설정 해시>_<데이터 지문>/` 아래 `bars_1m/`, `bars_1h/`, `bars_3h/` (월별 Parquet) | §2 규칙 적용 결과 | 제외 (`cache/`) |

- 엔진은 MariaDB에 직접 연결하지 않는다. 1단계 사본만 읽는다(C3 유지, 새 DB 의존성 없음).
- 1단계 사본은 원본 사본이므로 `data/`에 두고, 팀 공유는 F1(데이터 서버)의 `data/` 구조를 그대로 따른다.
- 2단계 캐시 이름에 넣는 값: `MINUTE_PREP_VERSION`(정규화 코드가 바뀌면 올림), `default.yaml`의 새 `minutes:` 절 해시, 1단계 매니페스트 해시. 셋 중 하나가 바뀌면 새 폴더로 다시 만든다. 일봉 `PREP_VERSION`과는 독립이라 일봉 준비 캐시를 무효화하지 않는다.
- 새 설정 `minutes:` 절(세션 시각, 가격 기준 허용오차 0.2%, NXT 기준일, 지원 봉 목록)은 `default.yaml` 맨 끝에 항목 추가로만 넣는다(공용 파일, 채널 사전 공지).

## 5. D-2 예측 출력 (P2-2, 제안 — Seonghwanaa 명시 결정 대기)

D-3은 "일봉 체결로 진행"으로 확정됐다(결정 §5.3). 그래서 분봉은 **예측·과거 검증의 입력**으로만 쓴다. 화면 표시는 E17(회색 구간과 방향만, 예상 캔들 없음)을 따른다.

| 항목 | 제안 | 근거 |
|---|---|---|
| 지원 봉 | **1일·1시간·3시간**은 기본 지원. **1분**은 아래 유동성 조건을 만족하는 종목만 지원하고, 아니면 `unsupported_liquidity` 실패 사유를 돌려준다(FR-F6) | §1.5. 거래가 드문 종목은 1분 행이 비어 1분 예측이 성립하지 않는다 |
| 1분 대상 유동성 | as_of 직전 20거래일 정규장 하루 평균 행 수 **≥ 360**(정규장 381분의 약 95%), 그리고 유니버스 조건(보통주·20일 평균 거래대금 5억 원 이상)을 함께 만족 | §1.2. 거래대금 5억 원 이상인 날의 행 수 중앙값이 365 |
| 예측 봉 개수 H (기본 / 허용 범위) | 1분 30 / 1~60, 1시간 **7** / 1~14, 3시간 **2** / 1~4, 1일 **5** / 1~20 | 분봉 기본값은 **봉 개수로 정규장 하루 분량**이다(1시간봉 7개, 3시간봉 2개). 달력상 "다음 거래일"이 아니라 as_of 다음 봉부터 센다. 예: 11:00 as_of의 1시간봉 H=7은 당일 남은 5개 + 다음 거래일 2개. 일봉은 1주 |
| 출력 값 | 각 미래 봉 h=1..H마다 마지막 확정 종가 대비 누적 로그수익률의 **10%·90% 분위(회색 구간)**와 **상승 확률**. 화면은 구간을 가격으로 바꿔 그리고, 방향은 **"통계적 방향"**으로 이름 붙여 상승 확률 0.55 이상이면 "상승 쪽", 0.45 이하이면 "하락 쪽", 그 사이는 "불확실"로 표시하고, E17 고정 문구(과거 데이터 기반 통계이며 매매 신호·투자 권유가 아님)를 항상 함께 둔다. 최종 화면 문구는 codex-01a0fb4b(화면 담당)와 맞춘다. 중앙값은 내부 채점용이며 선으로 그리지 않는다 | E17, FR-F7. 확정 가격처럼 보이는 단일 예측선과 매매 신호처럼 읽히는 문구를 피한다 |
| 부분 봉 | **쓰지 않는다.** 예측 시점(as_of)은 봉 확정 시각에만 둔다(1시간봉은 매 정시, 마지막은 15:31). 진행 중인 봉은 입력에도 출력에도 넣지 않는다 | FR-F3, §2.1 |
| 수치 위치 | 위 값(지원 봉, H 기본·범위, 분위, 방향 임계값, 유동성 기준)은 `default.yaml`의 `forecast:` 절에 둔다(맨 끝에 추가, 사전 공지) | AGENTS.md §7 수치 파라미터 |

- 채점(P2-8): 같은 평가 구간에서 단순 기준선(마지막 값 유지·과거 변동성 구간)과 비교한다. 지표는 구간 적중률(실제가 10~90% 구간 안에 든 비율, 목표 80%에 가까운지), 방향 적중률, 표본 수다. 백테스트 승률과 섞지 않는다. 미래 봉 h마다 **날 넘김 여부**(as_of 봉과 다른 거래일이면 밤사이 갭 포함)를 함께 표시해, slot별 보고와 같이 해석한다.
- 평가는 2026-04-24(NXT 통합) 전후 구간을 나눠 보고한다(N5).
