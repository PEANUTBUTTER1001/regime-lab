## 3. 공통 PR 절차와 완료 조건

1. **브랜치:** `develop`에서 새로 만듭니다. 이름은 `<종류>/<WBS ID>-<영문 설명>`입니다. 예: `feat/P3-8-rss-forward`, `docs/P3-3-source-ledger`
2. **커밋·PR 제목:** Conventional Commit 형식(`feat:`·`fix:`·`docs:`·`test:`·`chore:`)
3. **PR 본문:**
   - WBS ID와 변경 요약
   - 세 테스트 명령의 결과 줄(통과·skip 수)
   - 바꾼 공용 파일과 그 파일의 주인(협업 규칙 §4). 해당 주인을 리뷰어로 지정합니다.
   - 버전 상수 변경 여부
   - 실행하지 않은 검증(실제 API 호출 등)
4. **AGENTS §5 순서:** 설정 → 도메인과 단위 테스트(절단 불변 포함) → 유스케이스 → API → 웹(한국어·영어) → 조립 → 테스트
5. **완료 조건(AGENTS §8):**
   - 세 명령이 통과합니다.
   - 새 도메인 규칙에는 I/O 없는 단위 테스트가 있습니다.
   - 외부 자료 결합·선택 로직에는 절단 불변 검사가 있습니다.
   - §2·§4에 없는 위치에 파일을 만들지 않았습니다.
6. **pytest 임시 폴더**는 루트 `cache/` 아래에 둡니다(`--basetemp cache/...`). 상위 폴더가 없으면 먼저 만듭니다.

## C3. DB 이관·RAG 호환 조건

| 보존 대상 | 요구 조건 |
|---|---|
| 문서 식별 | `doc_id`·`version`·원출처 식별자/URL 유지. 재수집·재이관으로 동일 문서를 새 ID로 만들지 않음 |
| 검색·필터 입력 | 제목·회사명·출처·종목 연결과 연결 상태 보존. 제품 색인은 제목·회사명만 유지 |
| 시각 | `published_at`·`first_seen_at`·`available_at`·`time_precision`·시간대 보존. DB 이관일을 최초 수집일로 덮어쓰지 않음. 모르는 과거 관측 시각은 임의 복원하지 않고 기존 observed/historical_assumed 정책 적용 |
| 변경·삭제·권한 | 기존 버전 이력·내용 지문·삭제 상태·`license_scope` 유지. RAG의 `status == "deleted"` 가정과 수집 계약의 대응을 확인하고, 삭제 반영 시점도 과거 조회 규칙과 대조 |
| 확정 자료·공백 | docs manifest의 schema/정규화/시각 정책 버전과 coverage 이력 유지. API 실패·부분 수신·공백을 0건 정상으로 대체하지 않음 |
| 색인 갱신 | 데이터 변경 지문·안정적인 조회 스냅샷·캐시 무효화와 색인 재생성 절차 명시. 현재 서버 시작/`rag-index` 경로에 새 갱신 결과가 반영되는지 검증 |

- **주가 수신은 F1a 확정 경로:** 데이터 서버 API → 기존 store 형식의 새 로컬 Parquet 폴더 → 로컬 경로 전환. 엔진 loader 유지, 원본 덮어쓰기 금지. 접속값은 `REGIME_DATA_API_URL`·`REGIME_DATA_API_TOKEN` 환경변수만 사용.
- **기사 수신은 호환 우선 협의:** DB API → 기존 docs/coverage Parquet 형식 → 기존 검색 경로가 변경을 최소화하는 후보. 구체적인 API·동기화 공개 계약은 합의·필요 승인 후 구현. 서버 적재 전까지 기존 ext_store 파일 사본 공유 가능(F1a).
- **DB 직접 조회는 별도 변경:** 현재 `DocsStore`와 색인 생성은 파일 목록·지문 규약을 사용하므로 DB 주소만 바꾸는 전환은 아님. 직접 API 입력을 선택하면 저장소 연결부·캐시·갱신 처리 변경 범위를 별도 기록. 엔진에서 운영 DB 직접 접근으로 기존 경계를 우회하지 않음.
- **시트 단계에서 가능한 완료:** RAG 검색·화면·품질 평가. DB 연결·자동 갱신·정정/삭제 전달·이관 전후 일치 검증은 별도 완료 항목. 입력 계약이 같으면 검색·순위·평가 로직 재사용 가능하나, 수정량·즉시 전환 보장 불가.
- 기사 자료의 LLM 전송 범위는 변경하지 않음. 브리핑 v1은 집계 수치만 전송(D-7 v1); 기사 제목·요약·URL의 입력 확대는 별도 결정.
