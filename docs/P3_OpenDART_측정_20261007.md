## 방법

OpenDART `list.json`, 접수일 **2026-09-01~2026-09-30**, Y(유가증권)/K(코스닥)를 별도 조회했다. 모든 공시 유형, `last_reprt_at=N`(정정보고서 포함), `page_count=100`, `sort=date`, `sort_mth=asc`로 끝 페이지까지 읽었다. 요청 시작 간격 최소 0.5초, 측정 상한 1,000회, 요청 타임아웃 30초, 자동 재시도 없음이었다. 020·HTTP 오류·건수 변동/불일치가 발생하면 불완전으로 기록하고 중단하도록 했다.

기존 n8n의 DART 자격 증명을 메모리에서만 사용한 독립 측정이다. n8n 워크플로 실행/변경, LLM 호출, 시트 저장은 하지 않았다. 개별 공시 내용·원문·키를 저장소/채널에 공유하지 않고 집계 수치만 기록했다. PR #21 CLI 실행 성능으로 오인하지 않도록 아래 시간은 **독립 API 순회 측정**임을 명시한다.

## 5년 요청량 추정

정확히 60개월을 같은 크기의 달로 가정한 **단순 외삽**:

- 요청 수 `79 × 60 = 4,740회`.
- 경과 시간 `40.739 × 60 = 2,444.34초 ≈ 40.7분`.
- 정책상 수집기 전용 요청 예산 10,000회/일을 사용할 경우 산술상 1일 예산 안이다. 2배 물량 시 9,480회, 3배 시 14,220회로 각각 1일/2일 예산이다. 운영 중 다른 호출과 재시도 예산은 별도로 뺀다.

실행 완료 시한이나 보장값이 아니다. 9월 한 달 표본이므로 사업/반기/분기보고서 집중 월, 시장별 변화, API 지연, 재시도, 저장·검증 시간을 반영하지 않는다. 실제 5년 실행은 월별 첫 페이지의 total_page로 남은 호출 예산을 다시 계산하고 한도 도달 시 커서에서 재개한다. 전체 5년을 먼저 호출해서 추정을 검증하는 방식은 이번 측정 범위에 포함하지 않는다.

`2021-01-01~2026-10-06`은 5년이 아니라 5년 9개월 이상이다. 60개월 산식으로 이 범위의 작업량을 설명하지 않는다. 실행 대상 기간은 소비 시세의 실제 범위와 맞춰 명시한다.

OpenDART 공식 가이드의 020 기준은 계정별 실제 한도를 보장하지 않는다. 수집기 예산과 공급사 응답을 함께 따르며 020이면 즉시 중단한다.
